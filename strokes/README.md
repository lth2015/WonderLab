# 笔迹测试数据

用 `?collect` 采集的真实笔迹（[02 §4](../docs/02-product-design.md) 的测试用例集），用来校准 [03 §6.2](../docs/03-ux-ui-design.md) 的判定阈值和笔性分界（[02 §5.1](../docs/02-product-design.md)）。

## 采集

1. `npm run dev -- --host`，在桌面或手机上打开 `http://<地址>/?collect`。鼠标和触屏分别采，尽量覆盖不同的设备。
2. 测试者编号只填 `P01` 这样的代号，**不要填姓名**，也不要另外记下代号对应谁。
3. 按提示画完 50 笔（10 种形状 × 5 次，含「画鱼的一笔」），最后点「导出 JSON」。
4. **不要要求参与者画快或画慢**，只说「照平时的习惯画」。校准要的是自然的笔性，不是表演出来的速度。

## 顺带收集：想对世界说的话（规则校准集）

画完笔迹后，请同一位同事在纸上或备忘录里**自然写出 5–10 句「你想对这个世界说的话」**。

- **不给示例、不提关键词、不展示「一句成境」的 10 句固定测试句**，也不说「它能下雨、起雾」之类的能力；只说「想到什么写什么」。
- 只记代号（与笔迹同一个 `P01`），不记姓名。征得同意后，修改规则时可以在路线图附录里引用原句，但不写是谁写的。
- 每人一份 `strokes/sentences-P01.txt`，一行一句。这些文件**已被 `.gitignore` 排除**，和笔迹一样只放团队私有存储。

检查本地规则怎么理解这些句子：

```bash
npm run sentences -- strokes/sentences-*.txt --out before.md   # 改规则前
# ……按路线图 §2 的四个条件改 src/engine/intent.ts……
npm run sentences -- strokes/sentences-*.txt --out after.md    # 改规则后
npm test                                                        # 含否定表达的回归测试
```

报告同时列出 10 句固定测试句的结果：**只记录，不作为调规则的目标**。改规则后它们的命中如果变了，如实写进路线图附录，不刻意维持 8/10，也不追求 10/10。

## 数据保管

- 导出的 `strokes-*.json` 放进本目录。这些文件**已被 `.gitignore` 排除，不提交到仓库**；需要共享时放在团队的私有存储里。
- 文件只包含测试者代号、开始时间、坐标、时间戳、画布和屏幕尺寸、指针类型，没有姓名、账号或设备标识。

## 校准

```bash
npm test                          # src/collect/dataset.test.ts 用本目录的文件检验判定表
npm run calibrate -- --sweep      # 或加 --out report.md 存成文件
```

报告列出：每种形状的判定分布、是否满足 02 §5.2 的验收、判错的笔和测量值、候选阈值，以及「笔性分界」（各指针类型的速度分布、建议分界、异常值）。

**报告给出的是起点，不是结论。** 先看各设备的分布形状和异常值：是统一一条分界、按设备分层，还是需要个体自适应，由人看了数据再决定。改了 `src/engine/classify.ts` 或 `src/engine/koi-style.ts` 的数值，同步更新 03 §6.2。
