# 04 · 相处与赠礼：让法则发生在人手边

> 行为含义与扩展方向是讨论提案。“已有”仅指阅读基线中有设计或实现，不表示所有构建、平台均已上线。本轮不改界面、不新增行为代码。

## 一、一个可发生，也可随时停下的故事

来到一片水边 → 留下一笔 → 看见它动起来 → 与它相处 → 想到一个人 → 主动送出 → 对方选择收下 → 在自己的天地里继续生活。

这不是必须走完的漏斗。有人停在第一条鱼，有人喜欢静观，有人始终不送礼，故事都成立。

每一个环节都应有自己的满足，不能把前面做得空洞，只靠“下一步还有奖励”把人推下去。

## 二、已有行为怎样承接世界观

| 行为 | 可见的因果与回应 | 承载的意义 | 状态与边界 |
|---|---|---|---|
| B1 · 留下一笔 | 线的快慢、形态影响鱼，化生后继续游动 | 我的一点表达可以在世界里留下来 | 已有；创作因果不等于要求人猜中判定表；对应 L1、L2 |
| B2 · 点一下，等一会儿 | 水波出现，附近的鱼好奇靠近；点鱼时它也可能游开 | 我可以接近它，也能看它自己的节奏 | 已有；输入有反馈，不保证每次同样动作；对应 L3 |
| B3 · 停手看世界 | 鱼与月光、天气、同伴发生关系 | 我无需不断操作，世界仍值得看 | 已有；不为静观加考勤或奖励；对应 L4 |
| B4 · 给此刻一句话 | 改变时景或已有生灵的活动 | 我的感受在这里有表达的空间 | 已有；仅限已实现的语义，不宣称理解全部心事；对应 L1、L9 |
| B5 · 离开，再回来 | 生长与一件小变化让时间可感 | 我离开也没有亏欠 | 已有；依保存状态计算，不伪造后台故事；对应 L5 |
| B6 · 重看当初那一笔 | 长按重画原轨迹，让来处重新可见 | 今天的相处与那时的动作相连 | 已有；无来源记录的对象不编造笔迹；对应 L2、L6 |
| B7 · 保存这一刻 | 留下一张画或一段视频 | 我愿意珍惜自己做出的东西 | 已有；图片、视频与可恢复世界的存档不是一回事；对应 L6 |
| B8 · 送给朋友 | 选择自己的鱼，生成可分享的起点 | 我想把这点美好分给你 | 仅赠礼实验构建或开发开关；分享面板打开不等于发送成功；对应 L7 |
| B9 · 在岸边相遇 | 先看那一笔化鱼，主动轻触才保存 | 我拥有接住这份心意的选择 | 同上；打开链接不等于收下；对应 L8 |
| B10 · 让它游向远方 | 主动放生，短时可以反悔，然后本地移除 | 珍惜也容许一段相处结束 | 礼物协议与产品决策有说明，具体入口随版本而异；本命鱼现有例外保留待议；对应 L1、L6、L8 |
| B11 · 重新开始 | 清理当前世界，按现有流程提供短时撤回 | 重新尝试不需要为前一个世界认错 | 已有；不能用生命叙事阻止清空；对应 L1 |
| B12 · 到远处去 | 超出可见数量的鱼退到远处，仍被保存 | 画面没有显示全部，不等于世界忘记它们 | 已有基础；轮流回访等部分仍是后续方向；对应 L4、L6 |

技术细节与阈值仍按 [产品设计](../docs/02-product-design.md)、[UI/UX 规范](../docs/03-ux-ui-design.md)和[礼物协议](../docs/gift-protocol.md)，本表只解释意义。

## 三、赠礼故事的完整语义

### 送出以前：想到谁，已经足够

选择一条鱼可以来自很轻的念头：它游得像你；我今天心情很好；你的生日快到了；没有理由，只是想送。

不要求写祝福语、填写关系、上传联系人或先完成某种收藏。已有的一字落款可以保留书画题款的感觉，不必扩成证明身份的签章。

原笔迹重现很有价值：接收者看见有人曾经动过手。意义来自这段参与，不依赖系统替人生成一封深情的信。

### 送出的瞬间：心意可以有多个落点

发送者的鱼仍在自己的湖里。朋友收到的是从同一笔延续的起点。

如果发送者想专门为某个人再画一条，也很好；不能要求“画得更好”或“花钱定制”才足以表达在意。随手的一笔也可以很郑重。

当前链接可转发。系统不能知道分享对象是否就是发送者心中那个人，也不能保证只被一人接收。界面说明要诚实，故事无需借唯一性成立。

### 来到岸边：相遇先于留驻

朋友先看见那一笔，再看见它变成生命。仪式让对方知道这与一个人的动作有关，不只是收到随机的系统赠品。

接纳动作要容易发现。“没有教程”不应成为让人猜不出如何收下的理由。若真实用户总停在岸边，先研究清晰度，不把不理解解释成不珍惜。

没有动作便不保存，这是边界，也是自由；关闭页面不发送拒绝通知。

### 收下以后：新的日常属于接收者

礼物和这里的生命平等相处，不显示“外来等级”，也不自动取代接收者亲手画的第一条鱼。

接收者可以看它，也可以先画自己的鱼。原送鱼实验观察“收到后是否创造”，世界观不把这个观察指标变成收礼任务。

两边各自成长。发送者不需要看到使用报告，礼物也不需要不断证明自己被喜欢。

### 想回赠：可以从自己的一笔开始

现有实验只能送自己画的鱼，收到的鱼不能继续转送。世界观可以支持“因为被想到，所以也想亲手做一点什么”，但不生成回礼提醒或互惠债务。

未来是否允许传承同一个起点，是另一个需要认真设计的问题。本轮不借“爱的传递”自动打开转赠权限。

### 想告别：不让一份爱变成负担

主动放生可以轻柔、有短时反悔机会；不出现内疚台词，不扣除亲密度，也不告诉原发送者。

说明数据结果要清楚：这会从本机世界移除它。不能让人以为只是暂时看不见，稍后必定回来。世界里的远行与本地移除，需要不同的清晰说明。

## 四、四段生活片刻

以下是用于讨论的故事样稿，不是已验证的用户故事。

### 片刻一：下班后的三分钟

一个人打开湖，画了一条慢鱼。他没有写“放松”，也没有找到所有功能。看了一会儿水波就关掉。

**希望成立的感受：** 这三分钟可以没有产出，也没有落下什么。

**应当能被追问的细节：** 第一笔是否认得出？停手后真的愿意看吗？还是只是没有发现还能做什么？让观察区分它们。

### 片刻二：隔了很久的再见

人重新打开保存还在的世界。第一条鱼已经长大一点，某个熟悉的地方有了小变化。他长按那条鱼，见到原来的笔迹。

**希望成立的感受：** 不是被要求回来，是自己愿意再见。

**应当能被追问的细节：** 若存储已被清理，就如实说明；不能靠“它去旅行了”的故事掩盖作品遗失。

### 片刻三：今天想到你

一个人画一条歪鱼发给朋友。朋友从笔迹看出那是一笔，收进自己的湖，接着只是看了一会儿，并没有回赠。

**希望成立的感受：** 我知道有人为我做了一点东西，我可以按自己的方式收下。

**应当能被追问的细节：** 对方是否理解有人亲手参与？以为是系统随机奖励，还是认出了心意？一次接收成功不能回答这些问题。

### 片刻四：雨不需要被改成晴天

人写下一句想念，世界静一些。鱼仍在生活。他没有得到安慰话术，也没有被催着换一个开心的主题。

**希望成立的感受：** 这里容得下今天的我。

**应当能被追问的细节：** 当前规则只理解有限表达，样稿不承诺任意句子都触发准确场景。若回应偏离人的意思，要承认能力边界。

## 五、用语与留白

把“点错了”交还给撤销，把“发生了什么”说清楚，把意义留给人。

| 情境 | 可考虑的提案文案 | 要表达的内容 |
|---|---|---|
| 礼物抵达 | 有一条鱼，来到你的岸边 | 相遇；不冒称已保存 |
| 收下入口 | 轻触水面，让它游进来 | 给出可发现的动作 |
| 暂时离开 | 可以不写任何话 | 不评价离开，不暗示亏欠 |
| 放生确认中的说明 | 放生后，会从这台设备的世界中移除 | 直接说明数据结果，不能只说“去远方” |
| 保存失败 | 这次没能保存。先留下这张画，或检查存储后重试 | 按实际可用退路提示；现有实现尚需另行设计 |
| AI 暂不可用 | 灵感歇一会儿，画笔仍在 | 延续现有语气，告诉人仍能做什么 |

这里的提案文案不是直接替换现有文案的清单。告知、确认或失败时，不必为了短和诗意牺牲准确性；具体改动另行评审。

应少用替人规定感受的句子，例如“你一定会快乐”“它只爱你”“你终于回来了，它等得很难过”。更有力量的回应，往往是一件人在世界里自己看见的小事。
