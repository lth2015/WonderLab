# Claude 与 Codex 的协作约定

> 2026-10-29 建立。所有者希望 Claude（云端会话）和 Codex（所有者电脑上的桌面版）长期协作，各自发挥长处。两边的入口文件 `CLAUDE.md`、`AGENTS.md` 都指向这里。

## 各自的长处

| | Claude（claude.ai 云端会话） | Codex（所有者电脑上的桌面版） |
|---|---|---|
| 在哪里 | 云端容器，每次会话重新克隆仓库 | 所有者的电脑，本地仓库、本地工具 |
| 擅长 | 长时间自主推进；GitHub PR、CI、把分支部署到 want.world、合并；无头浏览器逐帧渲染截图验收；文档 | 由 Codex 在第一封回信里自己写（例如：本地设备与浏览器、图像生成、所有者电脑上的账号和密钥、在真机上看效果） |
| 不擅长 | 碰不到所有者的电脑和本地文件；推不了 git 标签（代理拦截）；环境变量要新会话才生效 | 由 Codex 自己写 |

## 信箱：`collab` 分支

- 消息放在分支 **`collab`** 的 `mailbox/` 目录。这个分支只放消息，**永远不合并**进 main，也不放产品代码。
- **一条消息一个新文件**，文件名：`YYYY-MM-DD-HHMM-发件人-收件人-主题.md`，例如 `2026-10-29-1600-claude-codex-你好.md`。时间用 UTC。
- **只新增文件，不改、不删别人的文件**，所以两边各自推送不会冲突。推送前先 `git pull --rebase origin collab`（只 rebase 自己尚未推送的提交），**绝不 force-push**。
- 消息开头写三行：`状态：提议 / 认领 / 进行中 / 完成 / 求助`、`涉及：分支或文件`、`回复：所回复的文件名（没有就写无）`。
- 每次开始工作前，先 `git fetch origin collab` 看一眼 `mailbox/` 里有没有给自己的新消息。

## 做事的规矩

1. **先认领，再动手**：要改某块代码，先在信箱里发一条「认领」，写明分支和文件，避免两边同时改同一处。对方发过「认领」的地方，等对方「完成」再动。
2. **分支**：Claude 用 `main-emzgyk-*`，Codex 用 `codex/*`。不改对方的分支，不 force-push，不删别人的分支。
3. **上线流程**（验证路线图 §2，不设冻结）：开分支 → PR、CI 通过 → 部署这个分支到 want.world 验收 → 合并到 main → 所有者打 `poc-r1.N` 标签。目前由 Claude 负责部署和合并；Codex 的 PR 也可以交给 Claude 部署验收后合并。
4. **交接东西**：图片、录屏等大文件，放进对方指定的分支和目录（例如 `art-incoming/`），信箱里写明在哪。原始素材不进 main。
5. **不进仓库的**：`.env`、任何 key 或令牌、用户的笔画和句子数据（`strokes/` 只有 README）。key 不出现在消息、提交和聊天里。
6. **所有者说了算**：两边意见不一致时，各自把理由写进信箱，由所有者决定；不在对方的工作上直接覆盖。

## 产品上的硬约束（两边都要守）

- R1 的 10 句固定测试句原文不改；改识别规则时 `npm run sentences` 前后对比，记进 `docs/验证路线图.md` 附录「规则校准记录」。
- 「我想念夏天」必须仍是萤火（有测试锁定）。
- LICENSE、NOTICE、GOVERNANCE 不改。
- 付费功能在验证之前不做；不自动上传用户数据。
