# 主持测试工具包 · 阶段 D

阶段 D 要用 5–10 名成年测试者（约一半用手机、一半用桌面），通过两段式主持测试，判断 H1–H3 各自成立、不成立还是不确定（[02 §1](../02-product-design.md)、[§8](../02-product-design.md)、[§9](../02-product-design.md)）。这个文件夹是做这件事要用的全部材料。

| 文件 | 用途 | 什么时候用 |
|---|---|---|
| [主持人手册.md](主持人手册.md) | 流程、逐字话术、主持人操作、访谈提纲 | 开测前通读，测试时放在手边 |
| [观察记录表.md](观察记录表.md) | 每位测试者一张，打印或复制使用 | 测试过程中填写 |
| [知情同意书.md](知情同意书.md) | 测试前请测试者阅读并签字 | 每位测试者开始前 |
| [notes.example.json](notes.example.json) | 求助及 H3 主动性证据的电子版格式（示例为虚构数据） | 全部测完后整理 |

详细的判定、旧数据迁移和开测参数锁定清单见 [测量有效性审查.md](测量有效性审查.md)。

## 一页流程

1. **开测前（一次）：** 读完手册；把手册里标着「开测前定稿」的几个数定下来；准备测试链接（带 `?mod`）；按手册第 2 节检查设备。
2. **每位测试者：** 签同意书 → 用主持人链接打开一个全新的世界 → **引导段**（只说一句话）→ 切到**自由段**，主持人离开 → 测试者叫你或到时间后回来 → **冻结 H3 观察** → **导出日志** → 访谈（含「一句成境」10 句）→ 填完记录表 → 重置，换下一位。
3. **全部测完：** 把日志放进同一个文件夹，把记录表里的求助与 H3 观察结果抄进 `notes.json`，运行

   ```bash
   npm run analyze -- 日志文件夹/wonderlab-session-*.json --notes notes.json --out 验证报告.md
   ```

   得到 H1–H3 的结论和每个人的明细，再结合访谈写验证报告（结论 + 下一步建议）。

## 主持人操作速查

| 做什么 | 桌面 | 手机 / 平板 |
|---|---|---|
| 打开主持人面板 | — | 用 `?mod` 链接时，在**左上角**快速点 5 下 |
| 开始自由段 / 回到引导段 | `Alt`+`Shift`+`P` | 面板 →「开始自由段」 |
| 导出日志 | `Alt`+`Shift`+`E`（下载 JSON） | 面板 →「导出日志」（弹出系统分享，发给自己） |
| 换下一位（重置为全新世界） | `Alt`+`Shift`+`R` | 面板 →「换下一位（重置）」 |

左上角的 5 下点击不会进入测试者的日志。日志只存在这台设备的内存里：**刷新或关掉页面之前一定先导出**。没导出就重置时，会先弹窗确认。
