# 送一条鱼 · 协议、隐私边界与交互原型

> 2026-10-25 · 状态：**实验版本**。只在 `poc-gift-r1` 构建里可用（开发环境下用 `?giftlab`）；`poc-r1` 和以后的正式版本里拿不到。产品定义见 [02 §5.7](02-product-design.md)，实验安排见 [验证路线图.md](验证路线图.md)。

> 分享不是复制一个世界，而是让一个生命在两个世界之间延续。共享的是起点，不是未来。

## 1. 边界

- 不需要账户，不建立社交关系；不引入动态、评论、排行榜或社区。
- 用户主动发送，接收者主动收下：打开链接**不会**直接、永久地改变接收者的世界。
- 画作数据不经我们的服务器保存或处理。
- 送出的鱼保留原始笔画，进入新世界后独立成长；**不同步**两边的成长。它的起源属于创造者，进入湖里以后，它的未来属于接收者。
- 可匿名、可选一个字的落款、可放生。
- 第一版只能送自己画的鱼，不能把收到的鱼再转送（转送时落款归谁，以后再设计）。

## 2. 礼物格式 v1

### 2.1 链接

```
https://want.world/#gift=v1.<payload>
```

- 礼物在 `#` 之后。`poc-gift-r1` 构建发出的链接是 `/#gift=v1.…`；开发环境发出的是 `/?giftlab#gift=v1.…`。其他构建打开礼物链接时什么也不发生。
- `v1` 是协议版本。不认识的版本不解码，提示「这条鱼没能游过来」。
- `<payload>` 是 base64url（`A–Z a–z 0–9 - _`，无填充），长度上限 **1200 字符**，超过直接拒绝。

### 2.2 内容（二进制，按顺序）

| 字段 | 编码 | 说明 |
|---|---|---|
| 标志 | 1 字节 | 第 0 位：有无落款；第 1–2 位：指针类型（mouse/touch/pen/keyboard）；第 3–4 位：笔性族 |
| 花色 | 1 字节 | `VARIETIES` 的序号；未知时按第一种 |
| 种子 | 2 字节 | 0–100，精度 1/655 |
| 速度 | 变长整数 | 画面短边/秒 × 1000，上限 60 |
| 弯度 | 变长整数 | × 100，上限 4 |
| 点数 | 1 字节 | 2–48 |
| 笔画 | 每点 3 个变长整数 | 相对上一点的 dx、dy（单位：发送者画面短边的 1/1024，y 向上，zigzag 编码），dt（8 ms 一格） |
| 落款 | 1 字节长度 + UTF-8 | 可选；只保留一个字母、数字或汉字 |
| 校验 | 4 字节 | 以上所有字节的 CRC-32 |

只存恢复一条鱼所必需的信息：笔画的形状和快慢（相对它自己的起点，按画面短边归一化，所以在大屏、小屏上大小一致）、花色、种子、笔性读数、落款。**不存**位置、整个世界、成长状态、动画、发送者身份或设备信息。

### 2.3 长度（实测）

用合成笔迹的 250 笔开放曲线和鱼形轮廓（`src/gift/codec.test.ts`，含落款）：

| | 最短 | 中位数 | p95 | 最长 |
|---|---|---|---|---|
| payload 字符数 | 89 | 194 | 218 | 218 |

浏览器实测一条键盘画的鱼，整条链接 161 字符。**这是合成数据**，周一采集真实笔迹后要用 `strokes/` 的「画鱼的一笔」重新测一遍；上限 1200 留了五倍余量。

### 2.4 校验与不可信输入

- CRC-32 只用来发现**意外损坏**（复制时截断、聊天软件改了字符），**不是签名**：任何人都能改礼物内容并重算校验值。
- 所以解码后的礼物和存档一样当作不可信输入：每个字段限定范围，笔画跨度超过两个画面、时长超过一分钟、多余的尾部字节，都直接拒绝。落款只接受一个字母、数字或汉字。
- 任何解码失败都不抛错、不影响世界，只轻轻提示「这条鱼没能游过来」。

### 2.5 同一份礼物只收一次

- 礼物的 id 是它的 CRC-32（36 进制）。收下后记在本机 `wonderlab.gifts`（最多 200 个），鱼本身也带着 id 存进世界。
- 再次打开同一个链接：提示「它已经在你的湖里了」，不会再来一条。

## 3. 隐私边界

`#` 之后的内容不会随正常的 HTTP 请求发给服务器，但浏览器里的脚本读得到它，所以还要做到下面几条。

| 要求 | 现状（2026-10-25 审计） |
|---|---|
| 不向任何分析或错误监控服务发送完整 URL | 没有接入任何第三方分析、错误上报或监控 SDK。事件日志只在本机内存，主持人手动导出，不含 URL |
| 分享页面不把笔画数据传给远程 API | 页面唯一的远程 API 是「一句成境」的 `/api/scene`，只发那句话；礼物从不进入任何请求。浏览器实测：接收一份礼物的全过程共 74 个请求，没有一个含礼物数据 |
| 服务端不做链接预览解析或内容解码 | 服务端没有礼物相关代码。聊天软件抓取链接预览时同样拿不到 `#` 之后的内容 |
| Referer 不带出礼物 | 浏览器发 Referer 时去掉 `#` 之后的部分；服务端另设 `Referrer-Policy: strict-origin-when-cross-origin` |
| 读完即从地址栏移除 | 打开后立刻读出礼物并从地址栏删掉：刷新不会再来一次，复制地址栏也不会把礼物带出去 |
| 只有收到链接的人能拿到内容 | 礼物只存在于链接本身。我们不保存，也就无法替任何人取回；链接转给谁，由用户决定 |

以后接入任何分析或错误监控服务之前，必须先确认它不会采集完整 URL（含 `#`），并更新本表。

## 4. 交互原型（`?giftlab`）

### 送出

1. 长按自己画的鱼：当初那一笔重画一遍（02 §5.6），旁边出现「送给朋友」。
2. 一个小面板：「落款（可不填，一个字）」，默认空着，即匿名。
3. 「发送」：有系统分享面板就用它，否则复制链接，提示「链接已复制，发给朋友吧」。

### 收到

1. 打开链接，自己的湖照常出现。片刻后，**远处的水面上**缓缓出现一笔（送鱼人原来的轨迹和快慢，最长 4 秒）；有落款的话，落款像书画的题款一样出现在笔画结束处，不盖在鱼身上。
2. 这一笔化成一条鱼，在远处的湖边游动。地平线下方出现一行字：「一条鱼游到了你的湖边」。
3. **轻触水面**，鱼才真正游进湖里，游到你点的地方，从此存进你的世界，从这一天开始长大。
4. 不操作：鱼一直在湖边游，但**不会保存**，关掉页面就没有了。它也不占你的鱼数上限。

### 放生

长按收到的鱼：先重画送鱼人的那一笔（含落款），旁边出现「让它游向远方」。选了之后，鱼缓缓游向远岸、淡去，从本机世界移除。不通知送鱼人。

### 原型里已验证的（无头浏览器，两个独立的浏览器配置分别扮演送鱼人和收鱼人）

- 送出、复制链接、落款「月」；收鱼人打开后地址栏里的礼物立即消失。
- 收下前存档里没有这条鱼；轻触水面后才存入，带着礼物 id、落款和出生顺序。
- 再次打开同一链接：「它已经在你的湖里了」；损坏的链接：「这条鱼没能游过来」。
- 在已打开的页面里再点一个礼物链接（地址只变 `#` 之后，页面不重新加载）也能收到。
- 重画时落款出现在笔画末端；「让它游向远方」后，鱼从存档中移除。

### 还没验证、要在真机上看的

- 仪式的节奏：一笔 → 化鱼 → 在远处游，是否像「收到礼物」而不是「出了个 bug」。
- 「轻触水面」这个动作，没有任何说明时，收鱼人能不能想到。
- 落款的大小和颜色是否像题款。

## 5. 不影响现有 PoC

- 原有主持测试（H1/H2/H3）不变：正式界面没有「送给朋友」入口，测试者看不到这个功能。
- 「送一条鱼」作为后续独立实验。核心观察：**收到鱼的人，是否在自己的湖里画出了第一条自己的鱼**（`npm run analyze` 的「收到一条鱼之后」一节）。
- 事件日志（本机）：`gift_sent`（怎么发的、有无落款、链接长度）、`gift_shown`、`gift_accepted`、`gift_released`、`gift_failed`（原因）。都不含笔画或落款内容。
