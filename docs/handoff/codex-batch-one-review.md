## 应修复：流星鱼的同行关系在出生首帧被移除

位置：[engine.ts:1353](https://github.com/lth2015/WonderLab/blob/bda3711/src/engine/engine.ts#L1353)，同文件 meteorFish 的创建与 companions 登记；Fish.update 的 forming 阶段见 [fish.ts:454](https://github.com/lth2015/WonderLab/blob/bda3711/src/engine/fish.ts#L454)。

meteorFish 创建的鱼初始 state 是 forming，登记 companions 后，updateCompany 只保留两条鱼均为 swimming 的配对。因此，新鱼还在约 0.9 秒的出生阶段，同行关系已被首帧过滤掉；减少动态也有约 0.6 秒淡入，同样被过滤。此后转为 swimming，没有地方重建这次配对。这会使「天赠鱼与人的鱼同行一段」在实际出生流程中失效。

在真实浏览器引擎上分别使用普通和减少动态设置，都取得相同状态序列：

| 时点 | 天赠鱼 state | companions 长度 |
|---|---|---|
| 调用现有 meteorFish 后 | forming | 1 |
| 按现有引擎推进 1/60 秒后 | forming | 0 |
| 再推进 3 秒后 | swimming | 0 |

证据在 art-incoming/reviews/pr93/report.json，复现脚本 review.cjs。脚本使用本地隔离的已合并代码，在浏览器里抓取实际 Engine 实例，只设置鱼的位置以保证附近有合适同伴，再调用现有出生入口和 update；没有修改生产文件。

建议：保留仍在 forming 的有效配对，在它进入 swimming 后再施加同行引导；已离开、被撤销、已移出世界的鱼仍及时清理。最好让 10–14 秒的同行从可游动时开始，并补一项覆盖「出生 → 成形 → 同行 → 各自离开」的行为验证。修后我可用同一条真实出生路径复核；不建议用直接把新鱼改成 swimming 的检查代替出生过程。

## 可以更好的两处生活细节

1. 同行目前按固定屏幕左右偏移，并稍稍朝上；鱼转向后，位置不一定仍是身体侧后方。先保证出生流程有效，随后若观感像追逐，可按同伴朝向计算侧后位置，保留“短暂同路”的轻盈。
2. 月光偏爱的固定偏移可以作为第一步。月亮靠画面边缘或很小时，后续可让偏移随实际光路宽度与可达水域调整，让“光路边缘”更贴着看得见的光。此项是创作与观感建议，本轮未将它作为确认缺陷。
