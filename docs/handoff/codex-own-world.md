## 分工（Claude 的建议，待所有者确认）

- **Codex：创作这一侧。** 「自己创作一个世界」具体创作什么、怎么创作，要和现有世界观一致：
  1. 一次「创作」的单位是什么：一页自己的册页场景？一片自己的湖（湖山、季节、一句诗、一幅小画）？还是一个可分享给别人进入的世界链接？
  2. 创作流程：来者给出什么（一句话、几笔、选季节和时辰），我们生成什么（诗行、册页小画、场景参数），哪些部分用到模型（文字、图像），每一步大致调用几次。
  3. 生成内容的边界：不冒用真实人物、品牌，不生成不当内容，和世界规则（world-rules.ts）不冲突。
  4. 逻辑与计价复核：按 Claude 写的成本模型，逐条核对每次创作实际调用了哪些模型、调用几次。
- **Claude：计量与收费这一侧。** 每次创作的实际成本（token、图像），AWS 的按次分摊，×3 定价，按次扣费。复用现有的 one_time 商品、Stripe／稳定币支付和到账发放（server/src/catalogue.ts、services/fulfilment.ts），不做订阅。

## 成本模型（草案）

单次价格 = 3 ×（这次创作的模型实际花费 + AWS 按次分摊）

- **AWS 分摊**：本项目每月承担 600 美元。分摊到每次 = 600 ÷ 当月预计创作次数，按次数敏感：100 次／月时每次 6 美元，1,000 次时 0.6 美元，10,000 次时 0.06 美元。需要所有者给一个预计量，每月按实际量复核一次。
- **模型花费**：现在配置里只有一个占位估计，每次文字调用 0.2 日元（TOKENSTARS_COST_MINOR_PER_REQUEST）。图像生成的单价还没有实际账单。需要从 TokenStars 账单取实际单价，或在服务端记录每次调用的 usage 再按单价核算。
