# 印刷导出能力评估（为实物实验做准备）

> 2026-10-25 · 只是评估，**没有开发任何商业功能**。决策见 [02 §11 决策 11](02-product-design.md)、[§14](02-product-design.md)。

实物实验（「一条鱼的来信」艺术卡、「我的湖」A4/A3 艺术微喷）要求引擎能脱离屏幕分辨率导出高质量静态作品。现在就查清楚，免得到了商业化阶段才发现只能输出手机屏幕大小的 PNG。

## 1. 实测：现有「保存为壁纸」能导出多大

方法：无头 Chromium（软件渲染），各画 4 条鱼和月亮，调用 `captureWallpaper` 请求不同尺寸。

| | 桌面 1280×800 | 手机 390×844 |
|---|---|---|
| 现在能导出的最大尺寸 | 5120×3200 | **1560×3376** |
| 原因 | 像素倍率上限 4 倍屏幕 | 同左 |
| A3 300 dpi（4961×3508） | 长边够，短边 3200（约 270 dpi） | 远远不够（约 110 dpi） |
| A4 300 dpi（3508×2480） | 够 | **不够**：宽边 1560，约 190 dpi |
| 明信片 100×148 mm 300 dpi（1181×1748） | 够 | 够 |
| 一次导出耗时（软件渲染） | 27–50 秒 | 20–24 秒 |
| WebGL 上限（本环境） | 纹理、渲染缓冲 8192 | 同左 |

**结论：**「一条鱼的来信」这种卡片尺寸，现有导出已经够用。「我的湖」A4/A3，桌面创作者基本可以，**手机创作者不行**，而测试者大约一半用手机。

## 2. 要解决的问题

### 2.1 手机上分辨率不够（主要问题）

把倍率上限从 4 调到 8 理论上能到 3120×6752，但内存会出问题：画面目标、远山缓存（半精度浮点）、读回的像素加起来约 300 MB，iPhone 上的网页很可能直接崩溃。可行的做法是**分块渲染**：把一张大图分成若干块，逐块渲染、拼接。正交相机支持只渲染画面的一部分，但现在的全屏着色器用 `gl_FragCoord` 和画面尺寸计算位置，需要加一个「块偏移」统一变量。**估计中等工作量**，在决定做「我的湖」之前不需要动手。

### 2.2 画幅比例不同

屏幕是 16:10（桌面）或约 9:19.5（手机竖屏），A 系列纸张是 1:1.414。世界的位置按屏幕宽高分别归一化保存，换一个比例重新排布会把鱼和月亮**拉变形**（缩放时 x、y 分别缩放）。所以不能简单地「按纸张比例重新渲染」。

两个方向，需要产品和设计决定：

- **装裱式**：作品保持屏幕原比例，放在纸上，四周留出边框，边框上可以有作品名、日期和印章，像水墨画的装裱。不改动作品本身，实现最简单。
- **重新构图**：在纸张比例上重新排布天空和湖面。效果可能更好，但「印出来的和屏幕上看到的不一样」，而且要处理变形。

**建议先试装裱式**，打样时一起看效果。

### 2.3 美术素材的分辨率

锦鲤贴图长 1024 像素。按现有最大倍率导出时，桌面上最大的鱼约 800 像素长，手机上约 400 像素，都在贴图分辨率以内，印 A3 不会糊。如果将来要印 A2 或更大，或者手机改用分块渲染到 8 倍，鱼会超过 1024 像素，需要更高分辨率的贴图（`npm run art` 可以重新生成）。月亮、天空、水面、远山都是程序化绘制，没有分辨率上限。

### 2.4 真机上的限制（未验证）

本环境是软件渲染，WebGL 上限是 8192。真实 iPhone、Android 的纹理和渲染缓冲上限、可用内存、导出耗时都需要在真机上测；尤其是老款手机。

### 2.5 印刷时的隐私

现在的原则是「不上传用户画的内容」。实物订单不可避免要把作品图像交给我们和印刷商，所以下单流程必须：

- 明确告诉用户：这张图会发给谁、用来做什么、什么时候删除；
- 只发印刷用的图像，不发世界存档、笔迹或其他数据；
- 交付完成后按约定期限删除。

真实购买实验阶段是人工收单，这些也要写进知情说明。

## 3. 建议的顺序

1. **现在不改代码。**「一条鱼的来信」用现有导出就能打样。
2. 打样时，用桌面导出的 A4 图试「装裱式」版式，看看印出来的质感。
3. 等需求探索和打样都有结论、决定做「我的湖」之后，再做分块渲染和真机测试。
