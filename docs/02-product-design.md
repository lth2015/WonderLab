## 1. 要验证什么

**核心假设：** 用户会因为一次美妙的创造体验，**主动**发起下一次创造。

| # | 子假设 | 观察信号 | 判定成立的阈值（事先约定） |
|---|---|---|---|
| H1 | 无需教程，用户就能完成第一次创造 | 首笔时间、是否求助 | ≥80% 的测试者在 5 秒内无求助落下第一笔 |
| H2 | 第一次结果超出预期，驱动下一次 | 自由时间内的**无提示**创造次数、主动停手时间 | ≥60% 的测试者在自由时间内有 ≥3 次无提示创造 |
| H3 | 作品值得留下、给人看 | 录制完成率、主动要求保存/发送 | ≥30% 的测试者主动保存或询问如何发送 |

- **H3 主动性口径：** 仅计入引导段/自由段中、日志导出和访谈开始前，未经主持人提问、演示或保存/分享提示而自行保存作品，或主动提出保存/询问如何发送的行为。产品原有保存入口可正常使用。录制完成、保存事件本身不证明主动性；主持人问「你想怎么处理」之后的回答也不计成功。
- H3 使用 `notes.json` 的 `h3Observation.status`：`spontaneous`（主动）、`prompted_only`（只有被提示后的行为）、`not_observed`（完整观察窗口内未发生）、`unknown`（无法判断）。前三种必须附 `evidence`（原话/动作、阶段与时间、是否已有主持人提示）；缺失证据或旧 `askedToSend` 单独存在一律未知。明确否定必须记录 `windowComplete: true` 以确认完整观察窗口；有缺口不能填「未发生」。
- H3 未知保留在全部测试者分母，不从有效样本剔除：已知成功/N ≥30% 才成立；(成功+未知)/N <30% 才不成立；其余不确定。不改变 H1 ≥80%、H2 ≥60%、H3 ≥30% 的阈值。
- **H1 口径（2026-10-25）：** 计时从世界可交互开始。首屏那行「轻轻画一笔，看看会发生什么」是首屏本身的邀请（§3.1），**不算教程**，看到它之后落笔仍可计为成功。自动演示（一笔自己画出来、化成半透明的鱼）**是教程**：它在可交互 6 秒后才出现，落在 5 秒窗口之外；看过演示之后的第一笔不计 H1 成功（日志 `demo_shown`，`npm run analyze` 自动判定）。主持人的任何回答、示范仍按「求助」处理。
- “无提示创造”指不在情境提示出现后 10 秒内发生的创造（事件带 `prompted` 标记，见 §8）。
- 三项结论各自判为：成立 / 不成立 / 不确定。阈值是给 5–10 人的定性实验用的方向判断，不是统计结论。

PoC 不验证：付费意愿、长期留存、规模化成本。

## 2. 用户与场景

| 画像 | 场景 | 他们要什么 | 对设计的要求 |
|---|---|---|---|
| **路过的好奇者** | 朋友发来链接，手机或电脑上点开，注意力只有 10 秒 | 立刻看到有意思的东西 | 首屏零阅读、加载快、触屏与鼠标同等好用 |
| **爱分享的创作者** | 桌面浏览器，愿意花 10 分钟打磨 | 做出可以发出去的作品 | 录制质量、撤销、构图 |
| **陪孩子玩的家长**（PoC 之后） | 平板前和孩子一起 | 安全、简单 | 大触控区域、不依赖识字 |

- PoC 的测试者是 5–10 名**成年**受邀用户；儿童场景不在 PoC 测试范围内，但设计上不引入任何对儿童不安全的东西（外链、广告、自由生成的文字）。
- **设备：** 阶段 A 起就同时支持鼠标和触屏（同一套 Pointer Events），阶段 D 的测试者大约一半用手机、一半用桌面。charter 中阶段 C 的“移动端适配”在这里指：移动端的录制保存、软键盘、横竖屏等细节打磨。
- **微信内置浏览器：** 中文场景下链接多在微信里打开。PoC 要能检测出来：可以正常玩，点“录制”时提示「在浏览器中打开，才能保存作品」。

## 3. 体验主线

```
打开链接 ─▶ 看见活的世界 ─▶ 第一笔（目标 ≤5s）─▶ 线变成鱼
   │                                           │
   ▼                                           ▼
 无操作数秒 ─▶ 示范笔触              发现更多：触碰 / 画圆生月 / 一句成境
                                               │
                                               ▼
                                世界越来越丰富 ─▶ 录制 15 秒 ─▶ 预览 ─▶ 保存
```

### 3.1 首次进入（P0）

1. 首帧就是深墨底色（HTML 内联，无白屏），一滴淡墨晕开作为加载动画；天空、远山、湖面就绪后立即淡入，不等全部资源。
2. 世界一出现就在动：水波、云、星星闪烁。**湖里没有鱼**——第一条鱼留给用户自己画。
3. 湖面上方淡入提示「在湖面上画一笔」；桌面上光标变成笔尖。
4. 无操作一段时间后播放一次**示范笔触**：一道半透明墨线自己画出，化成虚影小鱼游走、消散，最多播放 2 次。示范期间点击虚影等同于用户自己落笔（示范立即结束，不会出现“点了没反应”）。
5. 用户落笔时，提示和示范立即淡出。

**“首次”按本次会话判定**，不读取历史记录。测试版本支持 `?fresh` 参数和主持人重置快捷键，确保每位测试者都从干净的世界开始。

### 3.2 渐进发现（P0）

情境提示每条按“**条件满足**或**超时**”中先到的那个出现；用户做到了就不再出现；被错过（出现时用户正在作画）可以再出现一次；提示只在作画间隙出现。

| 提示 | 出现条件（任一） | 位置 |
|---|---|---|
| 「点一点小鱼」 | 第一条鱼生成后片刻 | 鱼附近 |
| 「在天上画一个圆」 | 已触碰过鱼，或已画 2 条鱼，或进入后 60 秒仍没有月亮 | 天空 |
| 「写一句话，世界会听见」 | 月亮生成后，或进入后 90 秒仍未使用输入框 | 指向输入框 |

## 4. 输入判定

所有笔画先经过同一张判定表，**每个格子都有回应**（P3）。区域由笔画重心落在水天线上方还是下方决定。

| # | 输入特征 | 湖面 | 天空 |
|---|---|---|---|
| 1 | 位移 < 点按阈值，按住时间短 | 触碰回应（§5.4） | 触碰回应 |
| 2 | 位移 < 点按阈值，长按 | 鱼聚拢过来（P1；此前同 #1） | 一颗星闪烁 |
| 3 | 位移超过阈值，但路径很短（短笔） | 一圈小涟漪 + 墨点散开 | 化作一颗星点 |
| 4 | 闭合且**圆度高**（长宽比、拟合残差都在阈值内） | 月亮升到正上方天空，原位留下倒影 | 月亮 / 星球 |
| 5 | 闭合但**细长**（如鱼形轮廓） | 鱼（以轮廓长轴为脊线） | 一缕流云 |
| 6 | 开放弧线，累计转角落在“弧”的区间且圆拟合良好 | 鱼 | 新月 / 凸月（按转角定月相） |
| 7 | 其他开放曲线（含 S 形、螺旋） | 鱼 | 流星划过，最后化为星点。流星总是从这条线较高的一端落向较低的一端，往上画也一样（2026-10-28：往上飞的流星不合理） |
| 8 | 第二根手指落下 | 取消当前笔画，墨迹淡出 | 同左 |

- 判定阈值见 03 §6.2；阶段 A 用一套固定的测试用例调参：随手圆、歪圆、半圆、鱼形轮廓、S 形、螺旋、U 形、短划、点按，每类 10 人 × 5 次。
- 判定在抬笔后完成，并在一帧内给出结果，不调用 AI。
- 判错了怎么办：见 §6.1 撤销。

## 5. 四个核心互动

### 5.1 一笔化鱼（P0）

**输入：** 判定表 #5、#6、#7 的湖面格。

**从笔画到鱼的映射（P2）：**

| 笔画特征 | 鱼的属性 |
|---|---|
| 路径长度 | 身长（夹在上下限之间） |
| 平均曲率 | 摆尾幅度：直线利落，弯线柔软 |
| 绘制速度 | 性格：快笔灵动、游得快；慢笔悠闲、爱停留（再叠加每条鱼自己的脾性，见下） |
| 速度 × 弯度（笔性） | 花色的**倾向**，见下方「笔性」 |
| 收笔处 | 鱼头方向和初始游向 |
| 笔画形状 | 作为脊线，身体沿脊线生长 |
| 当前色板 | 墨色与点缀色 |

**笔性：笔画决定倾向，随机保留惊喜。** 这一笔的快慢、直弯把它归入四族之一；鱼有 75% 的几率来自本族花色，25% 来自其他花色（首轮实验参数，可配置）；**同一花色不会连续出现三次**（2026-10-28：手机上手指画的线多半慢而弯，原来这一族只有黄金，连画 8 条有 7 条是金色）。不是硬规则：用户不会因为摸清了规则，就为某种花色机械地画线。

| 笔性 | 主要倾向 |
|---|---|
| 快、直 | 红白、丹顶 |
| 快、弯 | 大正三色、昭和 |
| 慢、直 | 浅黄、墨鲤 |
| 慢、弯 | 黄金、丹顶 |

- **性格不与花色绑定。** 活泼程度 65% 来自这一笔的速度，35% 来自鱼自己的脾性，所以一条红白可以很安静，一条墨鲤也可以很活泼；独处或爱结伴同样是鱼自己的。
- **速度用归一化特征：** 以画面短边为单位、在粗采样路径上量，与画布大小、设备采样率无关；鼠标、触屏、触控笔各自分界（首轮值见 03 §6.2，用 `?collect` 的「画鱼的一笔」校准）。弯度在平滑后的路径上量，手抖不算弯。

**本命鱼：外观轻微不同，行为明显不同，情感意义逐渐显现。** 这个世界里用户画的第一条鱼。

- **外观：** 一侧胸鳍根部一点极小的朱砂，不改花色、不放大体型——它不该看起来像一条稀有鱼，而是「我的第一条鱼」。
- **主动回应：** 点空白湖面时，它从更远处、更快地游过来，但不是每次（约七成），否则显得机械。
- **自然成为核心：** 结伴同游时，别的鱼更愿意靠近它。
- **记得出生地：** 用户停手一阵后，它偶尔会游回最初落笔的地方。没有文字、没有提示。
- 鱼数超过上限时，它不会被挤走；撤销了第一条鱼，下一条画的鱼成为本命鱼；重新开始的新世界重新算起。

**规则不讲解，但可被发现：** 不主动说明花色倾向和本命鱼。测试时分别观察创作因果感（P2a）和作品归属感（P2b），测试前不得暗示「画法会决定花色」。

**每条鱼保留创作来源（开发约束）：** 原始笔画的归一化轨迹（≤ 48 点，含时间）、速度、弯度、笔性族、指针类型、生成的花色、随机种子和出生顺序，随世界一起保存在本机。将来可以让用户重新看到自己当初画下的那一笔，如何变成今天湖里的这条鱼——不需要大模型，也不增加推理成本。

**演化：** 墨线微微晕开 → 沿脊线长出身体和鳍 → 尾巴第一次摆动后游走，原地留下涟漪。

**约束：**

- 湖里同时游动的鱼有上限（按画质档位，见 03 §10）。超过上限时，最早的鱼游向远处、隐入水中（本命鱼除外），但**它仍属于这个世界**：存档里记着它「在远处」，湖里有空位时（撤销了一条鱼，或换到能显示更多鱼的设备上）它会在下次打开时回来，离开最久的先回来（决策 12）。设备变慢、上限降低时，多出来的鱼不会一次全部离开，每次创造最多两条。远处最多记 500 条（一条鱼存档约 2 KB，共约 1 MB），**任何一条都不会被删除**：远处满了，多出来的鱼就留在湖里（2026-10-26 决定）。
- 鱼之间会互相避让（P0）；结伴同游等群体行为是 P1。
- 鱼的点击命中区按游动方向向前预判，并且有最小命中半径（见 03 §6.2），保证在手机上点得中。

**验收：**

- 一条“快直线”和一条“慢弯线”画出的鱼，旁观者能看出明显不同。
- 鱼数量达到上限时，桌面中档设备保持流畅（帧率目标见 03 §10）。

### 5.2 画圆生月（P0）

**输入：** 判定表 #4（任何区域）和 #6（天空）。

| 笔画特征 | 月亮的属性 |
|---|---|
| 位置 | 月亮位置（湖面上画的圆映射到正上方的天空） |
| 大小 | 月亮大小（有上下限） |
| 闭合程度 | 月相：闭合 → 满月；接近闭合 → 凸月；半圆左右 → 弦月或新月（仅在天空） |

- 第一个圆生成月亮。之后的圆生成较小的星球（P1，最多 3 个，超过时替换最早的）；P0 阶段再画一个圆会把月亮移到新位置、换成新的月相。
- 月亮出现后：湖面有倒影；夜色略微变亮；鱼偶尔游向倒影。

**验收：** 随手画的歪圆识别成功率 ≥ 90%；鱼形轮廓被误判为圆的比例 ≤ 10%（以 §4 的测试用例为准）。

### 5.3 一句成境（P0；AI 部分在阶段 B 接入）

**画是主角，写是魔法。** 市面上已有大量「输入一句话 → 等待生成」的产品；我们的差异是「我随手画了一笔，竟然创造了一条生命」。所以文字不替代绘画，而是给已经存在的世界赋予新的意义：

| 层次 | 用户行为 | 系统回应 |
|---|---|---|
| 一 · 创造 | 画一笔、点一下 | 立即生成事物（只有画笔能创造生命） |
| 二 · 赋意 | 写一句话 | 改变世界的情绪、环境，以及**已有的鱼**在做什么 |
| 三 · 共创 | 继续画、写、触碰 | 已有世界与新的创造发生联系（§5.5） |

- 文字**从不直接生成鱼或月亮**。
- 写给鱼的话由鱼来回应（本地关键词与 AI 同一套枚举）：
  - 想去远方、看看外面 → `explore`：鱼各自游向离自己最远的湖边；
  - 在一起、团聚、陪伴 → `gather`：有 4 条以上就绕成一圈，否则聚到本命鱼身边；
  - 睡吧、休息、累了 → `rest`：鱼慢下来，浮近水面，约 20 秒；
  - 玩、跳、嬉戏 → `play`：一两条鱼先后跃出水面（减少动态效果时不跃）。
- 湖里没有鱼时，这些话只改变情绪和环境。
- 首页：输入框始终可见，但不抢主视觉。首屏提示「轻轻画一笔，看看会发生什么」，输入框占位符「告诉这个世界你在想什么…」（不再轮换示例句，免得它看起来像提示词工具）。
- 成本上也一致：画笔、点击、物理交互都在浏览器本地；只有理解文字才按需调用模型。
- 之后可以扩展「赋意」的对象（例如湖边的树开花、水面飘落花瓣），但每加一种都要先过艺术验收（P4）。

**输入：** 底部输入框，最多 50 字。

```
用户提交
  ├─▶ [立即 · 本地] 文字化为墨点飘入天空 —— “世界听见了”
  ├─▶ [立即 · 本地] 规则先给出变化：
  │      命中关键词 → 对应变化（“雨” → 开始下小雨）
  │      未命中 → 用情感词典判断倾向（明亮 / 低沉 / 平静），选择对应方向
  └─▶ [异步 · 服务端] AI 返回结构化场景指令
         ├─ 合法且在时限内 → 只补充本地没有设置的字段，平滑过渡
         └─ 超时 / 非法 / 被限流 → 保留本地结果，不打扰用户
```

**合并规则：** 本地规则已经命中的字段，AI 不能推翻（避免“先下雨，几秒后变成下雪”）。AI 只能补充本地没有设置的字段，以及调整强度。

**AI 场景指令（P0 范围，受约束 JSON，字段都是可选的，逐项校验）：**

```json
{
  "timeOfDay": "night | dusk",
  "weather": "clear | rain | mist | fireflies | snow | moonlit",
  "palette": "serene | warm | melancholy",
  "wind": 0.0,
  "intensity": 0.0,
  "fish": "explore | gather | rest | play",
  "echoId": 42
}
```

- 数值范围 0–1，越界截断；未知字段和枚举外的值一律丢弃。
- 枚举的扩展（雪、花瓣、黎明、更多色板等）在 P0 的每一项都通过艺术验收之后再加（P4）。

**echo 诗意回应（P1）：** AI **不自由生成文字**，只从一个预先编好的古诗词句库（约 150 句，公有领域，例如“野径云俱黑，江船火独明”）中选一个编号。画面上显示诗句和作者，几秒后淡出。

- 内容安全闭环：显示的文字全部来自人工审定的句库，提示词注入无法让画面出现不当内容。
- 字体闭环：句库的字符集是已知的，可以预先子集化字体（见 03 §4）。
- 时效：提交后超过时限（见 03 §6.3）才返回的 echo 直接丢弃，避免和用户的句子对不上。

**本地关键词兜底（阶段 A 实现）：** 约 60 个关键词 + 一个小的情感词典。例如：雨/下雨 → rain；雾/朦胧 → mist；下雪/小雪/中雪/大雪 → snow（小、中、大雪的密度依次增加，只有大雪带风）；月夜/月光/月色 → moonlit（请出月光，不生出月亮）；萤火/夏夜 → fireflies；黄昏/夕阳 → dusk；孤独/思念 → melancholy；温暖/开心 → warm。

**AI 访问控制与成本（P9）：**

- 必须经过服务端代理，前端不持有模型密钥。
- PoC 只对受邀测试者开放 AI：服务端签发可吊销的**邀请令牌**，令牌从链接读取后立即存入本地并从地址栏移除。没有令牌时，“一句成境”只用本地规则，体验完整可用。
- 代理校验 Origin 与令牌，并按 IP 限流。
- 三层封顶：每个令牌每日次数上限、全站每日费用上限、项目累计总预算上限。任意一层触顶都自动退回本地规则。
- 被限流时，输入框下方轻声提示（文案见 03 §13）。

**隐私：**

- 服务端不记录句子原文：代理关闭请求体日志。
- 缓存只保存“加盐哈希 → 场景指令”，设置过期时间。
- 选模型的准入条件：不将请求数据用于训练，数据保留期可配置或为零。

**验收：**

- 提交后立即出现本地反馈。
- 10 句典型测试句中，至少 8 句让测试者觉得“世界听懂了”。
- AI 服务关闭时，流程不报错，体验不中断。

### 5.4 触碰回应（P0）

| 触碰对象 | 回应 | 优先级 |
|---|---|---|
| 鱼 | 受惊，快速摆尾游开，水面涟漪 | P0 |
| 湖面空白处 | 涟漪扩散，附近的鱼好奇地游过来 | P0 |
| 短时间内再次点同一条鱼 | 鱼跃出水面，落水溅起水花（有冷却时间） | P1 |
| 月亮 | 月光短暂明亮，倒影荡漾 | P1 |
| 天空空白处 | 一颗星闪烁 | P0（成本低，避免天空无反应） |

- 落笔瞬间先出现墨点；如果最终判定为点按，墨点在抬手时化为涟漪或星光。
- 点按时，鱼的命中优先于湖面。

### 5.5 世界里的关系（P1）

**为什么：** 能做的事几分钟就能全部发现。之后继续画的理由，不能只是「再多一个东西」，而要是「世界里发生了一件事」（P5）。所以不加新物种（P4），让已有的东西互相发生关系，产生意料之外的结果。

| 关系 | 用户做了什么 | 世界的回应 |
|---|---|---|
| 月下跃鲤 | 画了鱼，也画了月亮 | 鱼不时游到月亮的倒影处，偶尔跃出水面去「够」月亮，月光一亮 |
| 雨中浮鱼、雾里鱼影 | 写了下雨或起雾 | 下雨时鱼浮上来接雨，水面点出小涟漪；起雾时鱼沉下去，影子变淡 |
| 雪夜 | 写了下雪 | 留白的雪花近大远小、慢慢飘；山头渐渐积雪，往下露出松林和岩石；雪不落在水上，湖面更暗更静、倒影更清楚；鱼游得慢、沉得深；水声和虫鸣退去，只留一点风声。参照马远《寒江独钓图》、柳宗元《江雪》：安静、慢，带一点思念，不是暴风雪 |
| 月夜 | 写了月夜、月光、月色 | **文字不生出月亮（画是主角），只请出月光**（2026-10-28）。画了月亮：月亮四周亮起柔光和一圈淡淡的月晕，湖上光路变宽变亮，远处水面细碎的银光，远山镶一道淡银边，星星变少（月明星稀）。没画月亮：夜色整体转为清冷的银蓝，左上角微光像月在画外，远水泛银、山有银边；稍后提示「在天上画一个圆」，画出月亮后月光聚到它身上。参照《记承天寺夜游》「庭下如积水空明」、《春江花月夜》「滟滟随波千万里」 |
| 群鱼成圆 | 画了 4 条以上的鱼，停手看着 | 鱼首尾相接绕成一个圆，游一会儿再散开；有月亮时月光一亮 |
| 流星入湖 | 在天上向下画一道流星，落到地平线附近 | 流星落进湖里，溅起水花，游出一条小小的黄金锦鲤（湖里最小的鱼），身下的水面微微发亮 |

- 这些是世界的回应，不是用户的创造：不产生撤销步骤，不计入 H2 的「创造」；事件日志单独记为 `emerge`，用来观察测试者看到之后是否接着创造。
- 用户永远优先：落笔时，正在成圆的鱼立刻散开。
- 时间和条件见 03 §7.1。

**验收：** 自由段里，看到「群鱼成圆」或「月下跃鲤」的测试者，之后 30 秒内有没有新的创造（观察记录）。

### 5.6 时间：离开再回来（P1）

**为什么：** 「人赋予生命以起点，系统赋予生命以变化，而时间赋予生命以意义。」以前关掉再打开，世界原样恢复，像按了暂停；离开一小时和离开一周看不出区别。

**原则：世界在你离开时也在过日子，但从不惩罚你离开。**

- 不做电子宠物式的愧疚：鱼不会饿、不会病、不会死；没有连续签到（P8）。
- 不推送通知召唤用户回来（PoC 与 iOS 首版都不做）。

| 机制 | 行为 |
|---|---|
| 离开期间的一件小事 | 离开 30 分钟以上再回来，世界里发生过**一件**小事：天上多了一颗星；或本命鱼正待在它出生的地方；或（离开几个小时、走时在下雨）雨刚停，水面还有余波。不弹窗、不写字。刷新页面、短暂切走不算离开；手机上后台挂着的页面重新回到前台也算回来 |
| 鱼慢慢长大 | 按真实经过的天数，约两周长到头：一般的鱼最多长 12%，本命鱼最多 18%，前几天长得最明显；颜色随之略沉一点。没有数值、等级或提示 |
| 看见当初那一笔 | 长按一条鱼：当初画下它的那一笔在水面上淡淡地重画一遍（原来的轨迹和快慢，最长 4 秒），鱼游回那一笔收笔的地方，墨迹随后化入水中。按在空白水面仍是「召唤鱼过来」。减少动态效果时整笔直接出现再淡去。流星化的鱼和旧存档里的鱼没有来源记录，长按按原来的方式回应 |

- 需要的数据都在本机：世界保存时间、每条鱼的出生时间（02 §5.1 的创作来源之外新增 `bornAt`）。
- 事件日志：`return`（离开多久、发生了哪件事）、`replay`（重看了哪条鱼）。
- **验证：** 主持测试每人只测一次，测不到回访。另做日记式测试：3–5 人在自己的手机上用一周，不催促、不提醒，看自然回来了几次、回来时说了什么（testkit/日记式测试.md）。

### 5.7 送一条鱼（实验，原型阶段）

> 分享不是复制一个世界，而是让一个生命在两个世界之间延续。

**为什么：** 「一个人的想象，成为另一个人想象的起点。」图片和视频是作品的展示，送鱼是作品的延续：我创造的生命，可以进入你的世界，并继续拥有自己的生命。

- 把自己画的一条鱼送给朋友：长按鱼 → 「送给朋友」 → 可选一个字的落款 → 系统分享。
- 朋友打开链接：远处水面上缓缓出现送鱼人的那一笔，落款像题款一样出现在笔画末端，化成一条鱼在湖边游动。**轻触水面才收下**；不操作就不保存。收下后它在朋友的湖里独立成长，两边互不同步：共享的是起点，不是未来。
- 收到的鱼可以「让它游向远方」：缓缓游出画面，从本机世界移除，不通知送鱼人。
- 不需要账户，不建立社交关系，不做动态、评论、排行榜或社区；画作数据只在链接里，不经过我们的服务器。
- 协议、隐私边界、交互细节和已验证的部分见 [gift-protocol.md](gift-protocol.md)。
- **现在只是实验**：只在 `poc-gift-r1` 构建里可用（开发环境用 `?giftlab`）。原有 H1–H3 主持测试不受影响，送鱼作为后续独立实验；核心观察是**收到鱼的人，是否在自己的湖里画出了第一条自己的鱼**。
- iOS 以后用 Universal Links 接收；先完成 Web 礼物链接，不阻塞 iOS 工程。

## 6. 支撑功能

### 6.1 撤销（P0）

误判一定会发生（例如想画鱼却出现了月亮），所以撤销必须随手可得。

- 每次创造之后，新创造物旁边短暂出现一个「墨散」小按钮，点击即撤销这次创造；几秒后按钮自动淡出。
- 桌面快捷键 `Cmd/Ctrl+Z`，可连续撤销。
- 被撤销的东西以墨散的方式消失。
- 「重新开始」放在“更多”菜单中，执行后提供短时间内可撤回的提示条（P1）。

### 6.2 录制与导出（P0，阶段 C）

- 右上角「录制」→ 3-2-1 倒计时 → 录制 15 秒。录制期间可以继续作画。再次点击可提前结束。
- **录进视频的内容：** 画布、印章水印、echo 诗句和墨点文字——这些全部在画布内渲染，不使用 DOM 叠加层，否则 `captureStream` 录不到。界面控件和“录制中”标记不会录进去。
- **分辨率：** 录制期间锁定渲染尺寸，长边不超过 1080px，码率见 03 §10；录制期间不切换画质档位。
- **声音：** 如果声音已经开启（P1），一并录入；否则是无声视频。
- **格式：** 优先 MP4（H.264），不支持时用 WebM。
- **保存：** 移动端优先使用系统分享面板（`navigator.share` 传文件），可以直接存到相册；不支持时退回下载。微信内置浏览器中提示在系统浏览器打开。
- **中断：** 录制中切到后台或旋转屏幕，自动结束录制并保留已录制的部分。
- **预览浮层：** 「保存」（主要操作）、「重录」、「放弃」。关闭浮层前需要确认，避免误触丢掉作品。
- 不支持 MediaRecorder 的浏览器：隐藏录制入口，改为「保存这一帧」（PNG）。
- **P0 退出标准：** 桌面 Chrome 和 iOS Safari 能完整录制并保存；其他浏览器为 P1。

### 6.3 世界保存（P1）

- 世界状态自动存入 localStorage，刷新后恢复；状态可序列化、带版本号，为将来的“世界种子”做准备。
- 测试版本中，`?fresh` 会清空状态（见 §3.1）。

### 6.4 声音（P1）

- 环境声 + 互动音效（设计见 03 §12）。
- 第一笔之后以低音量淡入，右上角始终有声音开关，记住用户的选择。
- 静音时所有体验依然成立。
- **边界（决策 10）：** 声音是世界的一部分，不是创作工具。不做作曲、不让用户「演奏」鱼或水；用身体表达音乐情绪的「空气作曲」属于 YUHA。

## 7. 世界模型

```ts
interface WorldState {
  version: 1;
  seed: number;
  atmosphere: {
    timeOfDay: 'night' | 'dusk';
    weather: 'clear' | 'rain' | 'mist' | 'fireflies' | 'snow' | 'moonlit';
    palette: 'serene' | 'warm' | 'melancholy';
    wind: number;        // 0–1，同时决定水面波动
    intensity: number;   // 0–1
  };
  entities: Array<FishEntity | MoonEntity | StarEntity | CloudEntity>;
  history: Command[];    // 用于撤销
}
```

- 初始状态：night · clear · serene，远山、湖、满天星，没有月亮也没有鱼。
- 氛围变化全部是插值过渡。
- 用户操作、本地规则、AI 指令**走同一个指令入口**修改状态，便于撤销、回放和测试。

## 8. 度量方案

**原则：** 不收集个人信息，不记录用户写的句子，不上传画作。

**数据来源：**

1. **主持式测试（主要）：** 测试分为两段。
   - **引导段：** 观察员在场，只说“这是一个网页，你可以随便玩”。
   - **自由段：** 观察员告诉测试者“玩多久都可以，随时可以停下”，然后离开房间或关掉摄像头。主持人只看事件日志。
   - 测试结束后访谈。
2. **事件日志（测试版本）：** 只记事件类型、时间戳和必要的非个人字段。主持人在测试结束时用隐藏快捷键导出，不需要测试者操作。

| 事件 | 字段 | 用途 |
|---|---|---|
| `world_ready` | 可交互耗时、设备类型 | 性能 |
| `first_stroke` | 距离可交互的时间 | H1 |
| `demo_shown` | 第几次自动演示、距离可交互的时间（首次在 6 秒） | H1：演示之后的第一笔不计成功 |
| `stroke_classified` | 判定类别、区域、长度、闭合度、圆度 | 判定准确率 |
| `create` | 类型（鱼/月/星…）、`prompted`；鱼另记花色、笔性族、是否本族（`affinity`）、是否本命鱼、速度、弯度、指针类型 | H2；P2a 对照访谈 |
| `emerge` | 世界自己的回应（`moon_leap` 月下跃鲤 / `ring` 群鱼成圆 / `home` 本命鱼回出生地），不含用户输入 | 关系是否带来下一次创造（§5.5） |
| `touch` | 对象 | 玩法发现 |
| `text_submit` | 结果来源（本地 / AI / 超时 / 限流），**不含原文** | AI 价值 |
| `hint_shown` / `hint_followed` | 提示编号 | 发现链路 |
| `undo` | 被撤销的类型、距创造的时间 | 误判信号 |
| `record_start` / `record_complete` / `save` | 时长、保存方式 | 保存漏斗；H3 需结合主动性观察证据 |
| `tier_change` | 档位 | 性能分级 |
| `phase_change` | 引导段 / 自由段 | 区分两段数据 |

**观察重点：** 第二笔之前的停顿；“哇”、笑、叫别人来看；是否主动问能不能发给别人；自由段里什么时候停手、停手前最后做了什么。

---

**观察：创造的乐趣，还是陪伴的乐趣。** 画出第一条鱼后，测试者是马上想画第二条，还是停下来看看第一条鱼在做什么？`npm run analyze` 按日志分为「接着画」「先看」「没再画」三类（只作描述，不设门槛）；观察员同时记下对方当时在看什么、说了什么。两种行为都自然发生，才说明这里有让人反复回来的东西。

| 别人怎么发现这个世界（增长） | **方向已定（2026-10-26），在 P8 之内：作品自己把人带进来。** ① 作品带一枚安静的落款，不是广告：**壁纸加上和 15 秒录制相同的「万象」小印章**（现在壁纸没有任何印记）；印章是水墨作品的一部分，**永远不能付费去掉**（那是 P10 禁止的「解除限制」）；图片上不放网址、不写「来自某 App」。② 实物卡片背面，印章旁加一行很小的 `want.world`（不是二维码，见 §14.1）。③ **永远不做**：推荐返利、分享后解锁、弹窗求分享、作品上的大号品牌标识。④ **接受不精确的来源归因**：不接第三方统计，只用 App Store Connect 的汇总来源和访谈里一句「你是怎么知道它的？」。最自然的入口仍是送一条鱼（送鱼实验在验证） | 壁纸印章冻结后做（会改变保存出来的作品，而 H3 衡量的正是主动保存，不进 R1）；卡片小字随实物打样 |
| 「万象」印章本身该长什么样 | **已定（2026-10-26）：由团队设计师做一枚矢量印章，篆书白文。** 现在的印章是代码里临时画的（圆角方块加设备上的楷体，没有楷体就退回无衬线字），像 App 徽章，不像印。新印章：篆书、白文（朱底留白字）、方印、保留轻微的刻印不完美，只设计这一枚；交付纯路径的 SVG，不依赖字体，所有设备一致，实物上也清晰；由人设计、不用图像模型，保留过程记录（§14.4）；属于品牌素材，归所有者个人。用在录制、壁纸、实物卡片，以后可能还有 App 图标和网站。需求见 [seal-brief.md](seal-brief.md) | 设计交付后替换代码里的临时印章（与冻结后的改动一起合并） |
| 世界和作品要不要有名字（§14.1「我的湖」要保留作品名称） | **方向已定（2026-10-26）：只在保存那一刻可以题名，可以不填。** 保存壁纸或下单印刷时，出现一行可不填的「题个名字」，像书画的题款；首屏和玩的过程中都不出现，不打断「打开就画」，也不变成任务。名字只存在本机（和其他存档一样不上传），只在下单印刷时随订单交给印刷商（§14.4）；起过的名字存进世界，下次保存时预先填好、可以修改，世界就慢慢有了名字。题款用竖排小字，和日期、「万象」印章放在一起。送一条鱼的「一个字」落款是另一回事，保持不变 | 不进 R1（会改变保存流程，影响 H3）；放进冻结后的改动合集，题款版式等印章设计交付后一起定 |

## 13. iOS App Store 产品路线（2026-10-25 决策）

- **目标**：Wonderful World（官网 want.world）同步规划 iOS 正式发布，并明确以未来商业化为方向；PoC 核心假设 H1–H3、免费首发和先完成真实用户验证的优先级不变。
- **产品定位**：以手指画笔为主、文字赋意为辅的互动艺术世界。iOS 与 Web 共享世界规则、鱼的出生来源、交互语义和视觉语言；iOS 不另造一套玩法。
- **V1 最小完整体验**：离线可用的本地画鱼/画月/互动、本地世界持久化、可保存静态作品、系统分享；15 秒视频导出在目标 iPhone 上通过真实验证后纳入首发，否则明确降级为图片并如实描述。**iOS V1 的文字交互仅使用本地规则，不发送远程 AI 请求**；Web 的受邀 AI 实验继续按原三层限额独立运行。原因：服务端只接受来自 `PUBLIC_WEB_URL` 的请求（App 的来源是 `capacitor://localhost`）；AI 资格靠 `#invite=` 令牌，App 没有这种入口；三层封顶按邀请令牌计算，公开上架后没有令牌就没有成本上限（违反 P9）。以后要开，先设计按安装/设备的额度并用 App Attest 证明请求来自真实 App，再单独评审。
- **平台差异化**：使用 iOS 原生文件/相册保存、系统分享、触觉反馈（可关闭）及可靠的生命周期恢复；不得仅将网页嵌入 WebView 作为唯一价值。无需登录即可完成第一次创造。
- **商业化准备，不在 V1 强推收费**：设计可扩展的商品权益/订阅边界，但未确定商品、价格、付费墙；数字功能收费前评估 StoreKit、Apple 日本区适用的外部购买规则、税务和恢复购买。Web Stripe 不得直接视为 iOS 数字商品付款的默认方案。
- **身份与隐私**：以日本个人开发者账号为预期主体；用户接受 App Store 展示法定姓名，但要求避免不必要的个人敏感信息公开。Apple trader/联系信息展示、隐私政策、支持邮箱、隐私标签、数据使用及 SDK 申报须在提交前逐项核实；不能以“免费 App”自动认定无需披露。
- **首发地区与审核隔离**：App Store Connect 初次发行只选择日本；后续扩区需重新审查当地法律、trader/联系信息披露及隐私要求。iOS 包不包含账户、Google 登录、Stripe、加密货币支付入口或其非必要代码；不得只隐藏菜单。
- **名称**：App 与网页统一叫 **Wonderful World**（决策 6）；上架前检查 App Store 同名应用和商标。
- **发布路径**：先技术可行性与 iPhone 真机验证，再 TestFlight 内测，完成审核合规材料后申请 App Store 上架；不得用模拟器结果替代真机验收。具体执行见 [iOS 开发任务](ios-development-plan.md) 与 [iOS 验收](ios-acceptance.md)。

## 14. 商业化（2026-10-25 决策）

> 创造自由，商业克制（[01 P10](01-product-principles.md)）。Wonderful World 是一家以数字创造为起点的艺术与情感体验品牌，而不仅仅是一款 App。

现阶段不追求 ARPU、付费率或订阅收入。要先证明两件事：人们愿意创造一个属于自己的世界（H1–H3、日记式测试）；他们愿意把这个世界的一部分留在生活里，或者送给别人（实物实验）。前者决定产品有没有生命力，后者决定它有没有自然的商业价值。

### 14.1 第一个商业实验：实物作品

只做两款，不做卷轴、摆件、服装等衍生品（SKU 一多，实验就变成供应链项目）：

| 商品 | 内容 | 验证什么 | 测试售价（待验证的假设） |
|---|---|---|---|
| 一条鱼的来信 | 高品质艺术卡：正面是用户创造的鱼，背面是原始笔迹、出生日期、「万象」印章和一块手写空白（第一批不印二维码，见下） | 是否愿意把创造**送给别人** | ¥980–1,480 |
| 我的湖 | A4 或 A3 艺术微喷，保留创作日期、作品名称和独特构图 | 是否认为自己的作品**值得长期收藏** | ¥2,980–3,980 |

售价是测试用的假设，正式收费前必须核算印刷、包装、物流、支付手续费、损耗和人工成本。

**「一条鱼的来信」的版式（2026-10-25 决定）：**
- **第一批不印二维码。** 送一条鱼要等送鱼实验的条件达到才并入正式版（验证路线图 §7），而实物在 H3 达标后就可能开始，早于送鱼实验的结论。二维码如果指向实验构建，收卡人会进入可能被撤下的版本，D 组以外的人也会在实验期间收到鱼，污染送鱼实验。所以卡片先单独验证「愿不愿意把创造送给别人」；送鱼并入正式版之后，才出带二维码的版本（扫码，那条鱼游进收卡人的湖，§5.7）。
- **背面：** 原始笔迹（每条鱼保存的那一笔，最多 48 个点，按卡片尺寸印成墨线，§5.1）、出生日期、「万象」印章，以及一块留给买的人**亲手写字**的空白。手写不经过任何系统，没有隐私问题，这才是真正的「来信」。
- **正面：** 第一批样品用现有的「保存为壁纸」导出，裁出那条鱼（[print-readiness.md](print-readiness.md)：卡片尺寸现有导出已够），不写新代码；要不要专门做「单独渲染一条鱼」，看过样品再定。
- **工程放到冻结之后：** 笔迹印成矢量墨线需要少量代码，等 H3 达标、决定进入真实购买（验证路线图 §7）之后再写。现在只做印刷询价。

### 14.2 两个阶段

| 阶段 | 规模 | 目标 |
|---|---|---|
| 需求探索 | 5–10 人（主持测试、日记式测试的访谈） | 理解作品的情感价值、自用还是送礼、价格预期和顾虑 |
| 真实购买 | 20–30 人，逐步招募 | 真实下单率、价格接受度、交付体验 |

- 不只问「愿意花多少钱」：口头意愿和实际付款之间差距很大，结论以真实付款为准。真实购买阶段最看重：多少人真正付款、收到后是否满意、是否愿意再送给另一个人。
- 不做假入口（放个购买按钮测点击、点了再说没货），那是 P8 禁止的误导。
- 真实购买阶段人工收单与交付，不开发支付系统。订单必然要把作品图像交给我们和印刷商，下单前要说清给谁、做什么、何时删除（[print-readiness.md](print-readiness.md) §2.5）。

### 14.3 实施顺序

1. 完成 H1–H3 主持测试，确认创造体验本身成立。
2. 完成日记式测试，看用户是否主动回来、保存或分享。
3. 增加实物意愿访谈：自用、送礼、价格、顾虑（[testkit/日记式测试.md](testkit/日记式测试.md)）。
4. 设计两款样品，找日本的印刷商打样，确认真实成本。
5. 小规模真实购买，人工收单与交付。
6. 根据结果决定是否产品化，再考虑自动下单、印刷 API 和物流。

**渲染能力准备**（不是商业功能）：印刷需要脱离屏幕分辨率导出。评估结果见 [print-readiness.md](print-readiness.md)：卡片尺寸现在就够；「我的湖」在手机上分辨率不够，需要分块渲染，并先决定版式（建议装裱式）。

### 14.4 开源、NetX 与权属

Apache-2.0 本身允许任何人商业部署这些代码；真正的差异化是品牌、持续的艺术创作、内容品质、服务体验和用户信任，不是限制别人使用开源代码。商业化之前要和 NetX 谈清楚：

**所有者立场（2026-10-25，待与 NetX 书面确认；许可文件 LICENSE / NOTICE / GOVERNANCE 届时再改）：**

| 资产 | 归属与方向 |
|---|---|
| 核心程序、交互引擎 | 所有者的捐赠，继续以 Apache-2.0 开源 |
| 已公开的美术素材（如锦鲤贴图）、将来公开的免费素材 | 所有者的捐赠：以 Apache-2.0 许可给所有人使用，**不转让给 NetX**。已经以 Apache-2.0 发布的部分，他人取得的许可永久且不可撤销 |

| Wonderful World 名称、Logo | 归所有者个人（Apache-2.0 本身不授予商标权） |
| 用户创造的作品 | **永远归用户**。个人保留、传播都受保护。用户购买实物时，授权我们只为这一单印刷和交付使用作品图像，不做其他用途，交付后按约定期限删除 |

注意：

- Apache-2.0 允许任何人商业部署这些代码；差异化来自品牌、持续的艺术创作、内容品质、服务和用户信任。
- 由图像模型生成、缺少足够人类创作参与的素材，在日本和不少国家可能不受著作权保护或保护较弱。商业素材应有明确的人类创作，并保留创作过程的记录。
- 以上是产品层面的方向，不是法律意见；与 NetX 的协议、用户条款和实物订单的授权说明，定稿前请律师审阅。

### 14.5 不启用的模块

从 yuha 移植来的积分账本和稳定币支付，是为「每次 AI 生成都有边际成本」设计的；Wonderful World 的核心创造几乎没有服务端成本，引入积分只会让产品变复杂。决定：**不启用**，将来在 Wonderful World 的生产构建中彻底排除（不只是关闭入口），以减少安全、合规和维护负担。iOS 构建已经按此要求剔除（§13）。
