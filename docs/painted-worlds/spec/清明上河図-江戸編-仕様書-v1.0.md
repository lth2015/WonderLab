# 清明上河図：江戸編

## 企画・開発実行仕様書

版：1.0｜作成日：2026年10月31日｜開発担当：Claude Code｜所属：WonderLab／Wonderful World（want.world）

本書は『江戸日本橋の対話型ミニゲーム』原案を見直し、中国編と共通の理念から再構成した独立した開発仕様書である。企画、画面、会話、案内、検証報告は日本語で統一する。コード識別子、パス、製品名は技術上の表記を用いる。本書の構成案は、既存リポジトリを調査済みであることを意味しない。

## 1. シリーズの出発点

**絵巻の中を歩き、町を知り、そこで暮らす人を知る。**

町のにぎわいは、名もない人々の仕事、行き来、気遣いによって生まれる。プレイヤーは絵師の見習いとして町に少しだけ暮らし、人を観察し、言葉を交わし、小さな手助けをする。遊び終わると、自分だけの思い出が一頁残る。

目指す体験は三つ。「入ってみたい」と思う景色、「応えてくれた」と感じるやり取り、「あの人を覚えている」と思える余韻。歴史の知識は体験に添え、美術は発見を助け、生成会話は人物の表現を支える。

| 共通の土台 | 中国編の進む道 | 江戸編の進む道 |
| --- | --- | --- |
| 絵巻の散策、出会い、軽い手助け、記録 | 川と橋を介して人が協力する暮らし | 店、手仕事、商い、なじみの往来 |
| 主人公は人々を描く絵師見習い | 一つの川につながる人々 | 一つの通りで支え合う人々 |
| 一回の体験に一つの思い出を残す | 舟運、河岸、茶店、運び手の連携 | 店からの頼まれごと、職人の工夫、客との約束 |
| 欲しい内容を明確に購入できる | 河畔や郊外の物語へ発展可能 | 老舗、手仕事、季節の町へ発展可能 |

両作品の物語を同じ依頼の名前替えにしない。歴史設定と文化表現は各作品が所有する。江戸編の主な着想源は『熈代勝覧』であり、中国の『清明上河図』の日本での原本、直接の続編、同時代の作品という説明はしない。

## 2. 原案の評価と今回の決定

原案の長所は、町を歩くこと、人と商いに触れること、絵巻帳に経験が残ることを結び付けた点にある。この核を残し、制作と体験の焦点を絞る。

| 原案の課題 | 今回の扱い |
| --- | --- |
| 六地区、十八人以上、複数機種、長編を同時に制作 | 一地区の完成した体験から開始する |
| 体力、毎日の課題、火災への期限が散策を急がせる | 体力制限と連続ログイン義務を設けず、火災の予告を主軸から外す |
| 一日三百回の生成会話を低額定期券で販売 | 実測前に約束しない。体験版は台本で完結させる |
| 英語、LINE、携帯端末のアプリを初期から併走 | 初版は日本語のブラウザー版。各移植は別の判断とする |
| 貨幣、物価、食文化の異なる年代が混ざる可能性 | 年代ごとの資料確認と、史実・創作・調整値の区別を導入する |
| 直接販売なら法的義務を回避できるという説明 | 決済方式だけで適法性を断定しない。提供形態に応じて確認する |
| 共通エンジンへの同時修正 | 独立した二つのアプリと、最小限の共通契約を先に設ける |
| 埋め込みの工程表や大規模チームの概算 | 実行順、検証条件、成果物を本書で明示し、費用は実績から積む |

## 3. 名称、時代、作品との距離

開発上の名称は『清明上河図：江戸編』。利用者向けの副題案は『日本橋、ひと頁』とし、作品紹介には『熈代勝覧』に着想を得た創作であることを記す。名称の商用利用調査は別途行う。

舞台は文化二年、1805年頃の日本橋界隈を基にした春の町。『熈代勝覧』が描く日本橋から今川橋までの通りを、学びと創作の参照とする。原画の町並みを寸法まで再現した史実の地図とは称さない。

日本橋三越本店の紹介では、作品は作者不詳で、ベルリンのアジア美術館に所蔵されるとされる。原案にある1806年の火災は歴史の背景として扱えるが、完成を急がせる期限や終末の演出には用いない。最初の物語は町の日常が続くところで終える。

師匠と主要人物は創作とし、実在の絵師本人や直弟子を装わない。史実の店名、屋号、紋、看板を使う場合は時代、所在地、図像、現存事業者との関係を調べる。実装用の仮名店舗を、原画で確認できる店として紹介しない。

初期版では現代的な握り寿司の屋台を当然の1805年の風景として置かない。食べ物、価格、風俗は個別に確認し、未確認の題材はそば、茶、紙など確認可能な範囲に差し替える。紙や道具であっても、特定の商品仕様の根拠がなければ創作と明示する。

## 4. 誰に、何を約束するか

- 主な対象は、町歩き、歴史、美術、短い物語を楽しむ成人。親子利用にも配慮するが、学校用製品は後の独立企画とする。
- 一回5〜15分。一つの出会いは1〜3分程度で、途中退出できる。
- 初めての人が、歴史知識、速い反応、正確な手描きなしで参加できる。
- スマートフォンの縦画面を優先し、パソコンでも同じ物語を遊べる。
- 開始に会員登録を要求しない。カメラ、マイク、位置情報も要求しない。
- 画面の進捗率より、「誰の何を手伝ったか」が記憶に残る体験を重視する。

## 6. 最初の十分と基本の繰り返し

基本の流れは、気になる様子を見つける → 話しかける → 関わり方を選ぶ → 小さな手助けをする → 変化を見る → 絵巻帳に残す、である。次に進むか帰るかは自分で選ぶ。

| 目安 | 行動 | 必要な反応 |
| --- | --- | --- |
| 0〜10秒 | 通り、人、店先が見える。「絵巻に入る」を押す | 操作できる景色を先に見せる。音は別途本人が有効にする |
| 10〜30秒 | 風でめくれた紙を押さえる | 紙が落ち着き、店の人が礼を言う。先に説明書を読ませない |
| 30〜90秒 | 店先の一場面を選んで描く | 最初の一頁が出来上がる。描画の腕前は問わない |
| 1.5〜4分 | 届け物の包みを整える | 品物が相手に渡り、店先の様子が変わる |
| 4〜8分 | 茶店、道具店、落とし物から興味のある方へ | 二つ以上の自由な選択肢がある |
| 8〜10分 | 絵巻帳を開く | 実際に出会った人と出来事だけを振り返る。続けることもできる |

この時間は設計の目安で、制限時間ではない。8秒間何も操作しない場合に短い案内を出し、消せるようにする。導入で何度も自動移動しない。

## 7. 長い絵巻を気持ちよく操作する

縦画面の中央を町に使い、下部の入口は「絵巻帳」「持ち物」「近くのこと」の三つ。上部に場所、時間帯、設定を置く。所持金は取引時に詳しく見せる。全員の名札や通知印を常時重ねない。

| 操作 | 仕様 |
| --- | --- |
| 指一本で通りを動かす | 指に画面が追従する。8 CSSピクセルを超える移動はドラッグとして扱い、タップを取り消す |
| 小さな人物を選ぶ | 表示の大きさとは別に44×44 CSSピクセル以上の選択範囲を確保する |
| 選択範囲が重なる | 優先度で解決できなければ最大三つの対象候補を出す。毎回違う人物が開く状態にしない |
| 詳しく見る | 所定の近景へ移動し、戻ると元の位置を復元する。二本指の正確な操作を必須にしない |
| 会話 | 下から開き、人物と町を一部残す。会話内のスクロールは町へ伝えない |
| 視点の誘導 | 300ミリ秒以内を目安にし、取り消せる。動きを減らす設定では即座に切り替える |
| 巻物の向き | 章の導入と構成は右から左を基本とするが、指の移動方向を逆転しない |
| 遊びの途中 | 街のドラッグを停止し、「町に戻る」を明示する |
| アプリが裏に回る | 時間と音を止める。戻った時に失敗、失金、依頼消滅を起こさない |

「近くのこと」は今できることを三つまで表示し、選ぶと場所を短く示す。自動で依頼を消化しない。文字は原則16 CSSピクセル以上、150%へ拡大可能にする。絵巻の対象には文字一覧からも到達できるようにし、キーボード操作、見えるフォーカス、色以外の識別を提供する。

## 8. 六人の人物と店

最初の地区は歴史に基づく創作街区とする。仮名店舗は実在店舗の再現ではないと資料上で明記し、物語の質を先に検証する。

| 人物 | その人の事情と話し方 | 体験との結び付き |
| --- | --- | --- |
| 師匠・宗吉 | 無口だが、人を見る目は温かい創作の絵師 | 絵巻帳を見て、選んだ場面に合う一言を返す |
| 紙屋の手代・清太 | 店先の紙が風でめくれ、少し慌てている | 最初の手助けと写生 |
| 道具屋のおかみ・お紺 | 手入れを終えた小道具を客に返したい | 包みを整え、道具を届ける小話 |
| 茶店の主人・喜助 | 常連の癖を覚え、人の行き来をよく見ている | 客の好みに合わせる遊び、落とし物の手掛かり |
| 振売り・金次 | 商売帰りで忙しいが、道具を大切にする | 届け物を受け取り、品が役立つ場面を見せる |
| 町の使い・お春 | 持ち主が大事にしている手拭いを探す | 観察と聞き取りの小話 |

店名、氏名、関係、出来事は創作である。子どもを登場させる場合は台本のみとし、自由生成会話を付けない。

初回、依頼中、完了後、再会、断られた時の五状態を各人物に用意する。口調は人物の性格を先に決め、全員を同じ威勢のよい江戸弁にしない。初期設定は読みやすい現代日本語に軽い江戸の言い回しを添える。難語は押すと説明できる。濃い江戸言葉への切替は監修後に追加する。

## 9. 三本の小話

### 一頁目：風のいたずら

清太の紙を文鎮で押さえる。操作は一度のタップで成功する。その後「働く手」「店先」「通りの往来」から描く対象を選ぶ。構図と師匠の言葉が変わるが、報酬に優劣は付けない。最初の絵巻頁と12文を得る。

### 二頁目：いつもの道具

お紺が手入れした道具を金次へ返したい。品と包みの目印を照合して三つの手順で包む。プレイヤーは自分で持って行くか、使いに託して店先で見送るかを選べる。届ける場合は金次が道具を使う様子、見送る場合はお紺が気に掛けていた理由を描く。どちらも物語は完結し、重要報酬は等しい。後の回想で別の頁を補える。

### 三頁目：あの人の手拭い

茶店に残った手拭いについて、模様と結び目を観察し、二人の話を聞いて持ち主を確かめる。間違っても追加の手掛かりが出て、失金や永続失敗にはならない。返した後に、それを大事にする個人的な理由が分かる。探す対象をただ増やさず、人を知るところで終える。

全小話に、未発見、発見済み、進行中、提出待ち、完了、回想可能の状態を定義する。選択条件、必要物、消費、変更される風景、頁、報酬、回想規則をデータ化する。再会時は完了した出来事に応じた台詞を返す。

## 10. 二種類の短い遊び

**包みを整える。** 三つの品と目印を、形と模様で対応させる。ドラッグのほか、品を押してから置き場を押す操作でも完了できる。間違いは元へ戻し、二回続けて迷ったら任意の手助けを表示する。制限時間なし、初回30〜60秒。包み方の具体的な歴史解説を載せる場合は資料を別途確認する。

**茶店の気配り。** 二人の客の好みを読み、三種類の茶と菓子の組合せから選ぶ。好みは文字と図柄の両方で示す。確定前に選び直せる。正確な操作速度ではなく、人の話を聞いたことが結果になる。45〜90秒を目安にする。茶や薬に現実の治療効果を語らせない。

**写生は難しい描画試験にしない。** 対象と近景・全景を選ぶと、美術設計された頁が出来る。題箋や装飾を一つ選べる。基礎の鮮明な画像保存は無料。保存画面を閉じても、得た頁は消えない。

## 11. 時間、貨幣、なじみ

行動を制限する体力は設けない。時間帯は朝、昼、夕とし、物語の区切りで進める。自由に眺めているだけで店が閉まり、依頼を逃すことはない。一巡後は開いた時間帯へ戻れる。

江戸の不定時法は資料付きの読み物として紹介可能だが、初版で日の出・日の入り、緯度、旧暦を精密にシミュレーションしない。時刻表示は生活の雰囲気を示す。史実の時刻制度と簡略化したゲーム時刻を混同しない。

初版の決済単位は整数の「文」だけ。初期所持金60文、三本の小話の報酬は12文、24文、18文。茶と菓子6文、記念の題箋12文を仮設定とする。これらは調整値であり、1805年の実売価格として説明しない。物語に必要な品は無償で渡す。

両・分・朱と文の交換を初版の財布へ入れない。将来の資料解説では、金の単位関係と金銭相場を区別し、「一両はいつでも四千文」という固定の史実として教えない。相場遊びの採用には別の設計と年代確認が必要である。

報酬は一つの達成につき一度だけ。回想でお金は増えない。現実のお金で文を買うこと、譲渡、換金、広告視聴による補充は行わない。なじみは「初めて」「顔なじみ」「気の置けない間柄」の三段階とし、固有の出来事で進む。無限の会話や贈り物で数値を稼ぐ仕組みにはしない。

## 12. 台本と生成会話

体験版は台本で全機能を完成させる。生成会話は後の任意機能であり、切断しても依頼、買い物、絵巻帳、結末が成立する。最初から会話量の多さを価値としない。

採用する場合、実際の利用価値、待ち時間、入力と出力の費用、無料利用分を含めた採算を計測する。原案の一日三十回・三百回や月額480円を確定仕様にしない。上限と停止条件はサーバーで管理する。

入力は人物資料、審査済み知識、必要最小限の進行と文脈だけ。出力は台詞と許可された候補行動だけとし、買い物、報酬、所持金、実購入は確定的な処理で検証する。モデルにデータベースの直接更新、支払操作、任意の外部接続、コード実行を許可しない。プレイヤーの文から権限を増やさない。

台詞はおおむね60〜120字。2秒で取消可能な待機表示、8秒を超えた場合や利用枠不足時には、その場面の台本へ切り替える。二重送信と重複課金を防ぐ。生成文は即興の演技であると分かる表示を付け、資料に基づく解説と区別する。

子ども向け設定と子どもの人物には自由生成会話を使わない。現実の個人情報の入力を求めない。生の会話は原則として長期保存しない。記憶を本人が選んで有効にした場合は、見える短い要約を修正・削除できるようにする。端末保存とサーバー保存の違いを説明する。

日記は起きた出来事から組む台本を標準にする。生成を使っても、未体験の出会いや会話を追加しない。歴史カードは人が確認した資料に基づき、生成の推測で埋めない。

## 13. 美術、音、制作物の条件

『熈代勝覧』の通りを見渡す構図、細かな人物、線と淡彩を参考に、ゲームとして描き直す。江戸編は店先の連なり、暖簾、道具、包み、通りの間合いを大切にする。中国編の船、橋、衣装をそのまま置き換えない。

初期素材の最低構成は、連続する背景三区間、それぞれ前景・中景・後景の三層以上、主要人物六人の三状態以上、通行人八系統、場所四か所の反応、二つの遊びの素材、独立構図の絵巻頁十二枚、統一した操作図柄、朝昼夕の配色である。

一画面の美術基準と一人分の操作反応を先に完成させ、一つの小話で品質を確認してから素材を増やす。内部試作の仮素材は許容するが、一般向けの完成版に絵文字や幾何図形の人物を残さない。生成画像は手足、衣装、看板の誤字、継ぎ目、透過縁を確認する。看板は校正できる文字層で作り、生成の疑似文字を残さない。

石町の時の鐘を参照する場合も、位置と聞こえ方を調べてから設計する。全体として足音、呼び声、紙や道具の音を中心に、音楽には余白を作る。環境音、操作音、音楽を個別に調整可能にする。音は利用者の操作後に開始し、端末の消音設定を尊重する。無音で全内容を遊べること。音で伝える重要情報には画面上の反応を添える。

画像、音楽、声、字体、質感、参考資料について、由来と利用条件を記録する。古い絵であること、描き直したことだけを理由に、任意の高精細写真、商標、現存店舗の意匠を自由利用できるとは判断しない。博物館や店との公式提携を、許諾なく表示しない。

## 14. Wonderful World 内の配置

実装前に、実際のリポジトリの規約、構成、起動方法、経路、配信設定を調べる。以下は論理上の配置案である。既に相当する構成があれば、その規約を保ち、対応表を記録するために利用する。形を合わせるための大規模移設は行わない。

```text
WonderLab/
  apps/
    qingming-china/       中国編の独立アプリ
    qingming-edo/         江戸編の独立アプリ
  packages/
    scroll-contracts/    共通データ契約と検証
    scroll-core/         検証後に抽出する純粋な処理
  docs/
    painted-worlds/      仕様、資料、素材台帳、検証記録
```

Claude Code は `apps/qingming-edo/`、Codex は `apps/qingming-china/` を担当する。両者は独立して起動、ビルド、素材読込、保存移行、検証できる。既存の Wonderful World の体験と入口を保つ。新作の進行を既存体験の共通状態へ混ぜない。

**最初は契約を共有し、実装の共有は検証後に行う。** 初回は Codex が最小のデータ契約と互換サンプルを提案し、江戸側で確認した後に第一版として固定する。未統合の共通パッケージが他方の起動を止めないよう、必要なら各アプリに一時的な変換層を置く。

共通ディレクトリには同時点で一人の変更担当を置く。他方は別の変更提案を作り、並行して同じ依存関係の固定ファイルを上書きしない。共通処理を変える場合は両作品で検証する。歴史設定、物語、通貨の規則、販売商品はそれぞれが管理し、以後の道筋を拘束しない。

既存構成に適した技術を優先する。必要なら二次元描画用のライブラリを使うが、同じ一画面と実素材で、端末上の明瞭さ、反応、読み込みを比較して決める。既存の三次元機能があるという理由で重い三次元の町を作らない。文字、入力、ボタンと代替経路には意味のあるウェブ要素を使う。採用時の依存関係は実環境で確認して固定する。

## 17. 商業化の方針

**売るのは、もう少し歩きたくなる物語と、手元に残したくなる表現である。**

無料体験で三本の小話が結末まで遊べ、基礎の絵巻帳と鮮明な画像保存も使える。物語の終わり直前の課金、体力の販売、依頼の答えの販売、文の販売、有料の偶然性商品、強制的な動画広告は採用しない。

| 商品案 | 無料部分と購入価値 | 導入順 |
| --- | --- | --- |
| 日本橋の続きの巻 | 無料の小話は完結。新地区と新しい物語を買い切りで提供し、内容量と対応端末を事前表示 | 最初の販売実験 |
| 絵巻帳の装い | 基本の記録と保存は無料。追加の装丁、題箋、独自の構図を明示して販売 | 次の小規模実験 |
| 制作応援セット | 実際に受け取れる外観などを明示する。寄付、投資、将来の利益として説明しない | 需要確認後 |
| 文化施設・地域向け | 別契約で案内と催事を制作する。未契約の提携表示や現地特典はしない | 別の事業判断 |

仮の検証価格は、続きの巻600〜980円、装丁一式240〜480円。日本向けに販売する場合の税込想定であり、支払受付はまだ行わない。税、配信先、実際の制作費を確認してから決める。原案の月額通行証は初期商品から外し、継続して内容を提供できる実績が出来てから再検討する。

実決済を導入する場合、注文作成、決済事業者による確認、署名検証済みの通知、重複しない権利記録、権利取得、解放の順とする。支払後の画面遷移だけで購入済みにしない。再通知、通信断、返金、購入復元、端末変更を扱う。購入前に、会員でない利用者の権利復元方法を明示する。開発用の端末フラグを販売版の権利管理に流用しない。

収支は売上だけでなく、決済や配信先の費用、返金、変動インフラ、生成会話、問い合わせ対応を含めて測る。無料利用者の費用と制作素材の回収も別に見る。生成費だけが売上の一定割合に収まっても、全体の採算が取れるとは限らない。販売率や価格は仮説として記録する。

## 18. 分かち合いと再訪

共有するのは「今日、この町で出会ったこと」の一頁。絵巻の画像保存と本作へのリンクを用意する。端末の共有機能が使えない場合は、画像保存とリンクのコピーへ切り替える。共有は取り消せる。共有回数で報酬を与えず、友人を招かないと完成しない頁を作らない。

共有画像に本名、私的な会話、保存データを含めない。小さな作品名は入れてよいが、絵を覆わない。初版のリンクに入れるのは許可された作品・場面の識別子だけで、残高や報酬を改変する指示は含めない。受け手は公開体験からそのまま遊べる。

再訪の理由は別の視点、別の小話、新しい描写とする。連続ログインの義務や取り逃しの不安で戻さない。

計測は、入場、初回の有効操作、小話の開始と完了、絵巻帳の閲覧、保存の試行と結果、再訪、エラーに絞る。作品と会期を区別し、自由文は標準で送信しない。配信先に応じた同意の仕組みを実装する。共有ボタンを押したことと、相手へ実際に届いたことを同じ指標にしない。

## 19. 品質基準と利用者検証

基準端末として一般的な性能のiPhoneとAndroidを一台ずつ決め、型番、基本ソフト、ブラウザーを記録する。パソコンのChromeとSafariでも確認する。仮素材の空画面ではなく、本番に近い容量と密度で検証する。

| 項目 | 合格条件 |
| --- | --- |
| 最初の読込 | キャッシュなし、下り10 Mbps、往復遅延100ミリ秒の記録条件で、主要画面の操作可能時間の中央値5秒以内。三回以上の値を残す |
| 初期容量 | 最初の操作に必要な圧縮済み素材を合計5 MB以内とする。次の地区は必要時に読み込む |
| 画面の動き | 基準端末で二分間散策。目標は毎秒60フレーム、フレーム処理時間の95パーセンタイル33.3ミリ秒以内。文字をぼかさず、先に動きや描画解像度を調整する |
| 操作 | 重要な反応は100ミリ秒以内に開始することを目指す。通信待ちは別表示。ドラッグで人物を誤って開かず、会話の操作で町が動かない |
| 保存 | 進行確定後すぐ記録する。再読込、裏画面からの復帰、画面回転で達成を失わない。破損時は退避と初期化を案内する |
| 内容 | 三本がすべて完結し、重複報酬がなく、両方の遊びをタップだけでも完了できる。未接続のボタンや行き止まりがない |
| 見やすさ | 幅360ピクセルからパソコンまで主要操作を隠さない。文字150%、無音、動きを減らす設定、キーボードと文字の代替入口が使える |
| 独立性 | 中国編と保存が混ざらない。`/edo/` と独立した `/` の両方で素材が正しく読み込まれる。既存のWonderful Worldが動く |

成人5〜8人を対象に、進行役を付けた観察を行い、少なくとも半数は本書を読んでいない人にする。歴史に詳しくない人と、ゲームに慣れていない人も含める。操作の位置を教えずに記録する。

拡張へ進む内部基準は、入場から30秒以内の初回操作80%以上、10分以内に一つの小話を自力で完了70%以上、誰にどんな変化があったか話せる人60%以上、別の場所を自発的に探索する人が半数以上。実人数と端数処理を併記し、小標本を市場の証明にしない。達しない場合は入口、反応、物語を直し、内容数で埋め合わせない。

原案の翌日40%、七日後20%などを確立した業界標準として扱わない。公開後に対象集団、再訪の定義、離脱理由を決めて測る。短い満足した遊びを、単に滞在時間が短いという理由で失敗としない。

## 20. Claude Code の実行順

1. 既存リポジトリを読み、規約、構成、起動と配信経路、従来機能を確認する。構成案との対応、実行コマンド、影響範囲を記録する。
2. 江戸編を独立した子ディレクトリに置き、起動、最小の台本、絵巻帳、復元可能な保存を作る。共通契約は中国編と確認するが、他方の未完成を理由に止まらない構成にする。
3. 一画面の美術基準と「風のいたずら」を最後まで作る。実機で指の移動、選択、会話、最初の画像保存を確認する。
4. 残る二本、二種類の遊び、六人の状態、十二頁を完成させる。素材台帳と内容の根拠を整理する。
5. 状態遷移、報酬の重複防止、財布、保存移行、座標、配信パスとキャッシュ分離を検証する。両作品に影響する変更は両方で確かめ、既存製品も回帰確認する。
6. 利用者の観察結果を反映し、独立ビルド可能な体験版と配信手順を渡す。want.world の入口は設定で接続する。実配信、支払、生成会話はそれぞれの段階で有効にする。

各段階で、動くコード、起動とビルド方法、実際の画像または短い操作記録、検証結果、未達事項、次の作業を示す。画像だけで遊べる成果物の代わりにせず、ビルドの成功だけで実機の品質を宣言しない。実装の内部をなぞるだけの試験より、保存破損や二重報酬などの実際の失敗を防ぐ試験を優先する。

開始時の依頼文：

> 本書に従い『清明上河図：江戸編』を実装してください。既存のWonderLab／Wonderful Worldの規約と動作を確認し、既存体験を保ちながら独立した子ディレクトリで開発してください。最初に「風のいたずら」を遊べる状態まで完成させ、その後に三本の小話を仕上げてください。画面と物語はすべて日本語にし、台本だけで完結させてください。生成会話と実決済は初期状態で無効にします。実環境で分からない事項、未制作素材、未検証の品質は正直に記録し、仮の画面を完成品と説明しないでください。後に明示された場合を除き、一般公開、実際の課金、外部への連絡はこの開発作業に含みません。
