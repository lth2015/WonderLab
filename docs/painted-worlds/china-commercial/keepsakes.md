# 有意义、可买断与赠友的数字纪念品

这是所有者新增的产品方向。本轮已做可运行、可导出、可分享的内部设计样品；没有真实下单、付款、赠礼领取或权益恢复。经营主体、地区、币种、定价和正式内容承诺尚未确定，不能据样品推断有人愿意付款。

## 商品意义与交付建议

| 样品 | 对应的相遇与心意 | 可以送给谁 |
| --- | --- | --- |
| 平安纸签 | 《针脚里的牵挂》里“有人盼你平安”；柳枝、平安祝语 | 将要远行、很久没见的朋友 |
| 同行灯笺 | 《桥边留一盏》概念试样里“为归途留一盏灯”；灯笺、陪伴祝语 | 加班晚归、正在独自面对变化的朋友 |
| 茶暖小笺 | 《一席知味》里“记得对方一点偏好”；茶盏、休息祝语 | 想邀来坐坐、需要喘口气的朋友 |

价值假设是“我用故事里的东西表达对你的在意”，不是稀缺编号、转卖或升值。三件样品各有自用/赠友文字，1440×1800 PNG可真实下载、保存和自行发送给朋友。所有图片都写明“设计样品·尚未发售”“不含购买或赠礼权益”。不收集收件人的姓名、邮箱或祝词。

当前沿用简笔画册的柳枝、茶盏与新增矢量灯笺来验证方向。正式付费商品还需要专属插画、适合打印/壁纸的多尺寸交付和更丰富的祝语设计；不能把已有免费画册换个标记就收费。原故事、第14页城门故事和免费清晰导出仍可正常使用。

商业目录按 `one_time_buyout` / `perpetual_personal` / `giftable` 建模：一次性购买、长期个人使用、无订阅续费。这里的买断指该件数字内容的使用权，不是转让著作权，也不承诺商业再发行。正式商品页必须写明具体文件、下载/恢复方式、授权范围、赠礼份数及是否含买家自用副本；样品阶段不虚构这些已售条件。

## 已实现的内部演示

开发模式参数 `?study=souvenirs`，行囊→打开数字纪念小铺。商品3选1，用途“留给自己/送给朋友”，图片预先生成以保留分享按钮的用户手势。支持PNG下载、带文件系统分享、仅链接系统分享、复制/手动复制；生成失败可重试，取消分享不改免费进度。

样品链接仅含world、study、souvenir、purpose，过滤原URL的身份/邀请/订单字段及fragment。朋友在另一个开发浏览器打开后直达相应样品，钱包仍60文、画册仍为空，不会变成“已购买”。这不是正式兑换链接，在生产环境不打开研究小铺。正式赠礼应使用服务端签发的不透明领取码。

所有商品 `development/internal/price=null`，无下单按钮、支付适配器或模拟已购买开关。生产通过DEV分支与动态导入剔除研究组件；夜归与纪念品标题均不进入生产JS，给生产页面加参数也不能显示研究卡。

## 未来服务边界

`KeepsakeGiftService`仅为接口：可信服务端校验目录/价格创建结账，确认已支付订单后签发礼物，登录的收件人领取，恢复个人权益。本轮未接入现有额度/订阅服务，游戏文钱不是购买凭证。

`planGiftClaim`是纯函数规则草案，不能当作已实现的安全服务：未付款/撤回/未知世界或商品不发放；ready生成一次领取计划；同一收件人重试幂等，其他人不能再领。正式实现必须在数据库中以revision比较交换或事务原子写入“领取+授权”，并验证身份、支付、退款与撤销状态。客户端链接和客户端函数都无权授予商品，也没有“并发领取已安全”的结论。

## 验证和下一步观察

`validation/keepsakes/`包含六份真实PNG、手机截图、脚本、实际从设置导出的事件及结果。浏览器已覆盖：3款×2用途、文件分享/链接分享、取消、朋友新浏览器、剪贴板拒绝、真实canvas失败后重试、兴趣双击去重、无第三方请求、无购买事件、免费存档完全不变。系统能力用替身验证分支，尚非真机系统分享验收。

测试59项（含城门6项新增测试与纪念品6项），全量构建、独立构建和根/子路径生产烟测通过。合入城门后重新走通150%大字、刷新/回放、v2导入与第14页PNG，分享链接指向gate，事件也识别gate。
