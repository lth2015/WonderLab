## 长卷导出和更新的实现边界

现有运行代码：中国 `layout.ts` 的 24000 × 1200 是场景坐标、20 个瓦片；江户 `painted.tsx`/`world.ts` 是 14 段。**场景坐标不等于素材原生像素**；不能把扩大 Canvas 或插值宣传成原生高清。

导出需独立从资源清单按顺序合成整卷，不依赖当前视口已经加载哪些段。明确是否带人物、时段和落款，让用户在导出前看懂结果。默认尺寸应适合手机保存和发送；高分辨率遇到 Canvas/内存上限时，说明限制并提供降分辨率或分段选项。应检查 Blob、解码和 URL 生命周期，失败不扣资源、不写坏进度。J02 引入外部图像后，SVG→PNG 要内联所需图像，复用江户已有导出经验，防止保存出空白。

延长画卷时，处理位置、导览、热点、分段加载和镜头边界的共同变化。保持既有故事坐标和持久化 ID 稳定，旧存档按版本迁移；新增区域可由轻量更新提示或导览发现。中国与江户各自持续更新，不互相混用建筑、服饰、语言或故事设定。

## 当前框架是否值得持续投入

判断：**适合继续迭代已有规模的故事与互动；内容增多前应逐步模块化，不能直接当成无限扩展平台。** 此结论是当前代码评估，尚不等于多人并行、大规模章节或真人留存已经验证。

| 已有基础 | 支持的后续工作 | 需要改善的部分 |
| --- | --- | --- |
| 画卷分段资源、镜头/热点分离 | 增场景和新地点，不必整张重载 | 长度、资源数量、导览和边界仍散在常量里，需要统一章节清单 |
| 两作独立状态、稳定故事/画页 ID、存档迁移和一次性奖励 | 新故事、重逢、补画页，并保留老玩家进度 | 中国 `game.ts` 的 Action/QuestId/reducer 与 `App.tsx` 分支会随内容增长；逐步抽故事模块和注册校验 |
| 江户的内容定义、通用推进与中国已有独立故事面板 | 复用成熟规则，也能保留作品不同玩法 | 不为了共用而强制同构；用新故事实际验证新增成本 |
| 画页构图、PNG 导出和分享回退的既有实现 | 收藏、赠友画纸、文案选择 | 中国导出当前接收整个 GameState，含统计页脚；赠友渲染数据应只包含画、标题、赠言和必要落款 |
| 本机试玩记录与独立试玩会模式 | 观察首次操作、完成故事和分享困难 | 自动化不能代替真人判断；用 5–8 人观察找阻塞，再决定交互方向 |

下一次加故事应包含多一种有意义的参与，例如观察后做选择、摆放物件、帮助人物完成小事、行动后看见画面或关系变化。保留可点击替代操作与重逢，不要求玩家靠连续点“下一句”获得全部体验。

## 赠友画纸的内容要求

查到当前中国 `src/export.ts` 的 `exportPostcard` 会写入「今日记下 X 页 · Y 段相遇」，这是下一轮要移除的具体位置。当前游戏内「今日小记」的进度展示与对外图片分别处理；对外赠图不携带这些统计，也不要求收图朋友知道游戏任务。

- 从长卷或收藏页选一处景，选一句赠言，直接预览最终图片，再保存或分享。
- 画面为主，文字有留白，字体在手机里清楚；可有小落款，不让链接或营销信息抢画面。
- 同一张画可以表达不同心意。先使用经审阅的原创句库，按文艺、哲理、安抚、陪伴选择；江户篇另做自然的日文表达。
- 已有故事标题、画页 ID 与游戏存档不因更换赠言被重置。J02 保留现有标题与故事说明，赠友模式可另选面向朋友的文字，预览和导出使用相同渲染数据。
- 系统分享支持时发送图片；取消不算失败；不支持则可保存图片再发。付费数字商品的购买/赠送按正式商品流程另行实现。
